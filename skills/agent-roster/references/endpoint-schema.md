# Endpoint 台账格式

一个 Endpoint 一个文件：`<data_root>/agents/<host>/<kind>.md`。`<host>` 用 ssh 别名，和使用者既有的设备台账对齐，Host 本身的信息（地址、OS、规格）不在这里重复。

文件分成三段，**机器写的和人写的物理分开**：探测器只改「探测状态」，人与 agent 只改「任务倾向」，两边互不覆盖。

## 模板

```markdown
# <host>/<kind>

## 基本信息（probe 回填）

- **Agent Kind**: <kind>
- **CLI**: `<命令名>`（<版本>）
- **ACP 适配器**: `<适配器命令>`
- **模型**: <默认模型，探测不到就留空>
- **标签**: tier=<>, access=<local|ssh>

## 探测状态（probe 回填，只保留最近 1–2 条）

- YYYY-MM-DD HH:MM —— L1 ✅ / L2 ✅ ——（失败时写清楚卡在哪一层、报什么错）

## 任务倾向（人工维护，探测器不动）

- **擅长**: <自然语言描述，写具体场景而不是形容词>
- **不擅长**: <什么情况下会翻车>
- **注意**: <配额、速率、账号、上下文长度这类使用约束>

## 备注

<自由文本>
```

## 约定

- **不要加评分或枚举。** 任务倾向是自然语言，理由见 [ADR 0002](../../../docs/adr/0002-no-scoring-only-cases.md)。
- **「擅长」要写场景，不要写形容词。** 「大仓库里跨文件追调用链稳」是有用的；「能力强」不是。
- **探测状态失败时必须写清卡在哪一层。** 「没装」「装了但适配器起不来」「起得来但没登录」是三种完全不同的处置。
- **不写凭据。** 账号是否登录只记状态，密钥、token 一律不落文件。
- **模型字段允许为空。** 多数 CLI 的默认模型探测不到，留空比写错好。
