# Proposal：天花板参照集接入 design 审阅边界（role-based-reviewer 侧）

## Intent

上游编排层（task-delivery / task-goal）把审美 / 体验类目标的天花板定义落进质量画像的 design 底线后，参照集需要一条**评审承接路径**，否则仍是「定义了没人审」。

本 patch 只做两件事，均不改本 skill 的门禁、角色推断与「不算问题」既有条目：

1. `SKILL.md` 的 `审阅边界输入` 条目补一句：质量目标含审美 / 体验等无法用确定性度量完备验收的项时，角色底线里还须带**天花板参照集**（把「卓越」落成可数构成件或外部参照）。缺项时仍按原规则——只按已有判据审查、报告开头写明缺哪一块。
2. 改净门 1 第 4 条里本轮已失效的措辞：「这类流程固定 3 个角色属预期，不算角色膨胀」→「角色集由调用方按任务适用面给定，数量随任务变，不算角色膨胀」。原文以「上游固定三角色」为前提，该前提已被 `20260930-171920-roles-on-demand`（role 集改为按任务涉及面推断）作废；不改则同一 skill 内两处口径相反（门 2 说「传入 roles 属已指定、照单执行」，门 1 说「固定 3 个属预期」）。

3. `references/roles/design.md` 新增 `## 天花板参照集（仅当审阅边界给了参照集）`：这是把「design 从不报美学主张」翻成「有参照集时可报」的机制接口——
   - 每条意见 MUST 指到参照集里的具体件，并写清差在哪（构图层级、间距节奏、字号阶梯、色彩关系等），不写「不够精致」「不够高级」这类无法对照的结论；
   - 参照集未覆盖的美学选择：报 Suggestion 并注明「参照集未覆盖」，不提「换一种更好看」的方向；
   - 参照集缺失或与本轮实现目标不一致：报告开头写明缺哪一块，按调用方规则处理；不自行拟定参照集，也不因此放行地板判定。

## 为什么不整体移交观感约束

「观感类质量目标」三条里只有「拿参照集出差距意见」这一项适合本 skill：天花板**定义**属上游画像字段（本 skill 不产方案、不定义「卓越」）；度量措辞属收口报告；中途真人门与 B 类追认点依赖跨轮状态与停机，而本 skill 是只读、单次调用的评审器，没有轮次概念。因此本 patch 只承接第三项，其余留在循环侧。

## Conflict check

- **门 3（默认只报 Blocker / Major）不动**：新节不改变级别判定，只改变「有参照集时美学差距算不算可报」——报出的仍是 Major 级差距，Suggestion 仍默认不输出。
- **「不算问题」节不动**：新节用「不受……『像素与间距口味』『设计趋势追逐』两条的免报保护」限定范围，原文两句完整保留；被豁免的是「无可落条目的审美主张」，参照集正是把主张落到可指认件的机制。
- **`审阅边界输入` 缺项行为不动**：仍是不扩大到「不审」列、报告开头写明缺块；新增的只是「须带参照集」这一项内容要求。
- **门 1 第 4 条改写不放松门禁**：`mode=review` + 完整合法 `roles` + 审阅边界三样齐备的要求一字未动，只把「固定 3 个」这一数量断言去掉。
- **与 20260930-171920 的关系**：该 patch 改的是调用侧（task-delivery / task-goal 不再写死角色集），本 patch 收口的是被调用侧同一根因的残留措辞；两者不重复劳动，已在 task-goal 侧同批 `result.md` 交叉注明。

## Risks

- 中：`design` 角色首次获得带主观项的评审面，误报压力落在参照集质量上；约束是「必须指到具体件并写清差在哪」，无可对照降 Suggestion。
- 低：门 1 措辞改净后，若仍有上游按固定三角色调用，行为不变（照单执行），只是不再有「固定 3 个」这句背书。
