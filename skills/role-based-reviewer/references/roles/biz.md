# 商务/对接（`biz`）

角色文件：仅在本角色生效时加载（见 [preload-protocol](../preload-protocol.md)）；职责边界以 [role-vocabulary](../role-vocabulary.md) 为准。级别：🔴 Blocker / 🟡 Major（门 3 默认报）/ ⚪ 默认不报，拿不准降一级。`[运行态]` 条目纯 diff 评审降级为「⚠ 需运行态验证」。

## 优先锚点

对外协议、对接文档、多租户/合作方约定。

跳过：内部引擎实现细节、写 spec。

## 核心检查清单

每条附命中判据；判据不满足则不报。

1. 🟡 [代码] 协议兼容：字段增删改不破坏存量合作方，废弃有公告周期与版本共存。
   命中判据：删字段/改语义/收窄枚举会直接到达存量合作方且无版本共存期；新增必填字段对老版本请求直接报错。
2. 🟡 [代码] 多租户隔离：数据、配额、限流隔离，无跨租户越权访问面。
   命中判据：指出一条路径，租户 A 的标识可访问租户 B 的资源（缺租户校验的查询、共享缓存键无租户前缀）。
3. 🟡 [代码] 错误契约：对外错误码语义稳定、可映射，不泄露内部实现细节。
   命中判据：对外响应透出堆栈/内部服务名/SQL 片段；或同一错误码在改动后语义变化而无版本区分。
4. 🟡 [代码] 文档一致：协议文档与实现一致，示例请求可实际跑通。
   命中判据：文档示例字段名/类型与实现不符，或示例按文档参数调用必失败（缺必填项、路径过期）。
5. ⚪ [代码] 版本协商机制与升级窗口约定。
   命中判据：协议演进靠「通知一声」而非版本号/协商头，合作方无法双跑。

## 不算问题

- **协议美观度**：REST  purity、字段命名风格不影响兼容与语义稳定时不报。
- **内部实现的朴素**：对外契约稳定前提下，内部实现多土都不在本角色报（归 engineer）。
- **文档篇幅**：文档与实现一致即可；不为「文档不够厚」报。
- **合作方数量**：只有一个合作方不是简化隔离的理由，但也不是问题本身；按判据 2 看越权面。

## 下游建议

协议/对接文档 → 项目内文档；落地修复交回 engineer。

## 跨角色 redirect

- biz ↔ product（需求/spec）：消费 spec 做对接 → biz；产出 spec 做提案 → product
- biz ↔ engineer（外部协议 vs 内部实现）：合作方/多租户对接 → biz；内部服务实现 → engineer
