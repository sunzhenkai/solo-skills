# 运维（`sre`）

角色文件：仅在本角色生效时加载（见 [preload-protocol](../preload-protocol.md)）；职责边界以 [role-vocabulary](../role-vocabulary.md) 为准。级别：🔴 Blocker / 🟡 Major（门 3 默认报）/ ⚪ 默认不报，拿不准降一级。`[运行态]` 条目纯 diff 评审降级为「⚠ 需运行态验证」。

## 优先锚点

部署清单、CI、Helm/compose、监控与告警、配置/密钥管理。

跳过：业务代码缺陷根因、运营规则文案。

## 核心检查清单

每条附命中判据；判据不满足则不报。

1. 🔴 [代码] 回滚：发布无可回滚路径、数据迁移不可逆且无备份/补偿。
   命中判据：发布动作生效后无法在不停服的前提下回到上一版本（schema 单向迁移无 down、配置热写无前值快照），且无备份或补偿脚本。
2. 🔴 [代码] 密钥：明文入库、进镜像层、进日志；权限过宽（`*` / root）。
   命中判据：在 compose/Dockerfile/CI 变量/代码里找到明文密钥，或镜像层可 `docker history` 读出；权限声明为通配或特权且无收窄理由。
3. 🟡 [代码] 探针：liveness/readiness 语义错误、探活打到下游、依赖未就绪即放行流量。
   命中判据：liveness 检查包含下游依赖（下游抖动引发全量重启）、readiness 未等关键依赖就绪即通过、或两探针同路径同参数失去区分。
4. 🟡 [代码] 资源：无 requests/limits、无 HPA 依据、节点配额与亲和性风险。
   命中判据：容器未声明 requests/limits 且会与既有负载混部；或 HPA 指标与真实瓶颈无关（按 CPU 扩一个 IO 密集型服务）。
5. 🟡 [代码] 告警：关键路径无告警、告警无可执行行动项、无抑制规则会风暴。
   命中判据：面向用户的可用性断点无对应告警；或告警文案不含「看什么、做什么」；或同一根因会触发多条无分组的告警。
6. 🟡 [代码] CI/CD：构建不可复现、产物无版本锚点、发布靠手工单步。
   命中判据：构建依赖浮动版本（latest 标签、无 lockfile）导致两次构建产物不同；镜像/制品无 commit 或版本号锚点；发布流程含「登机器执行命令」步骤。
7. 🟡 [代码] 配置管理：环境间差异可解释、默认值显式、敏感配置走密钥管理。
   命中判据：同一配置项在多环境取值不同但无注释/文档说明原因；默认值靠「缺省即某行为」隐式约定；敏感项混在普通配置里。
8. ⚪ [运行态] 故障演练与容量评估结论有实测依据。

## 不算问题

- **「没有上 K8s/服务网格」**：编排与基础设施选型归项目阶段与约定，不因成熟度标杆报。
- **监控指标数量**：指标少不是问题；关键路径无告警（判据 5）才是。
- **手工步骤的存在**：低频、有手册、可回退的手工操作不报；只有发布主路径依赖手工（判据 6）才算。
- **资源规格偏好**：requests/limits 的具体数值品味不报，缺失或明显错配才报。

## 下游建议

`service-manager` → 本地服务生命周期验证；部署/CI 相关约定 → 项目内文档。

## 跨角色 redirect

- sre ↔ ops（灰度、配置）：基础设施（集群/部署/配置下发/告警）→ sre；业务侧（功能开关/运营规则/渠道配置）→ ops
- sre ↔ engineer（重启/OOM/稳定性）：集群·部署·调度·探针 → sre；代码缺陷·GC·调用链 → engineer
