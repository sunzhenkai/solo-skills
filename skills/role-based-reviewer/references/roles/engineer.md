# 研发（`engineer`）

角色文件：仅在本角色生效时加载（见 [preload-protocol](../preload-protocol.md)）；职责边界以 [role-vocabulary](../role-vocabulary.md) 为准。级别：🔴 Blocker / 🟡 Major（门 3 默认报）/ ⚪ 默认不报，拿不准降一级。`[运行态]` 条目纯 diff 评审降级为「⚠ 需运行态验证」。

## 优先锚点

目标服务/模块源码、接口、错误处理、性能热点、现有约定。

跳过：模型效果评估、离线口径。

## 核心检查清单

每条附命中判据；判据不满足则不报，不为凑数降级描述。

1. 🔴 [代码] 错误处理：catch 后吞错/只打印不处理、资源未释放（fd/连接/锁）、异常路径泄漏。
   命中判据：能找到一条具体执行路径，错误被吞后调用方无法感知失败或资源计数只增不减。
2. 🔴 [代码] 并发：共享可变状态无同步、check-then-act race、goroutine/线程泄漏、死锁风险。
   命中判据：指出两个并发执行体与共享对象，交错时产生错误结果或泄漏；读不出的并发问题不凭猜。
3. 🔴 [代码] 安全：注入面（SQL/命令/模板/路径穿越）、不可信反序列化、敏感信息硬编码或写入日志。
   命中判据：存在外部输入到危险汇（sink）的可达路径，且中间无校验/转义/参数化。
4. 🟡 [代码] 输入契约：边界校验缺失、错误码/异常语义不一致、接口破坏向后兼容。
   命中判据：给出一个合法输入触发非预期行为，或指出既有调用方会因签名/语义变化而破裂。
5. 🟡 [代码] 性能：N+1 访问、热路径不必要分配、无界缓存/队列、重试无退避放大风暴。
   命中判据：指出放大点（循环内 IO、每次调用都分配的大对象、无上限数据结构），并能说明量级随什么增长。
6. 🟡 [代码] 幂等：写操作对重试/重放/双击安全。
   命中判据：同一请求到达两次会产生重复副作用（重复扣减、重复创建、状态错乱），且无去重键/状态机兜底。
7. 🟡 [代码] 与现有约定一致：分层、命名、错误处理模式跟随代码库现状，不另起炉灶。
   命中判据：同一文件/模块内已有明确先例，新代码偏离先例且无理由；仓库无先例时不报。
8. 🟡 [代码][方案] 结构选择的依据：改动引入或更换架构 / 接口 / 技术栈时，依据（模式或原则）与换来的可检后果能否说出。
   命中判据：指出该选择对应的具体变化点或重复点；指不出则报，指出但模式与其不匹配（贴名而无收益）也报。方案评审按方案稿判定，纯 diff 只看已落地的结构。
9. ⚪ [代码] 可观测：关键路径日志/指标/tracing 埋点（采集与告警配置归 sre）。
10. ⚪ [代码] 复杂度：超长函数、深嵌套、重复逻辑；过度工程（为推测性未来需求建的抽象）同样算复杂度问题。
11. ⚪ [运行态] 性能实测数据支撑热点结论（火焰图/压测），不凭读码断言。

## 不算问题

- **风格偏好**：格式、命名口味、注释风格等个人偏好，只要与仓库现状一致就不报；要提也只能作 Suggestion 并明确标可选。
- **推测性 future-proof**：「将来可能要扩展所以这里应该抽象」——当前没有第二个使用者时不是问题，反而是复杂度风险。
- **理论完美的错误处理**：每个分支都兜底但不改变任何行为的冗余防御代码，不当作缺失报。
- **测试数量不足本身**：先看 qa 的覆盖缺口判据；engineer 不因「测试少」单独报，只报实现缺陷。
- **模式命名**：名字本身（工厂 / 策略 / 观察者）既不是问题也不是依据；按它是否消掉具体变化点或重复点判断，没有可检收益时并入复杂度条目，不为命名单独报。

## 跨角色 redirect

- engineer ↔ sre（重启/OOM/稳定性）：集群·部署·调度·探针 → sre；代码缺陷·GC·调用链 → engineer
- ops ↔ engineer（服务内业务开关、规则）：配置/灰度/运营异常 → ops；代码缺陷 → engineer
- biz ↔ engineer（外部协议 vs 内部实现）：合作方/多租户对接 → biz；内部服务实现 → engineer
- design ↔ engineer（UI 落地）：视觉与交互规格 → design；实现与性能 → engineer
- qa ↔ engineer（测试）：覆盖/回归/可测性 → qa；实现正确性 → engineer
- engineer ↔ algo（推理/排序服务）：可用性·性能·发版 → engineer；模型效果·策略·实验 → algo
- engineer ↔ data（事件/追踪管道）：在线可用性 → engineer；数据流与口径 → data
