# 失败：goal 模式下把协议级等待登记成任务并空转

- date: 2026-09-29
- 来源：一次 goal 模式下的复杂交付闭环（task-delivery 编排），真实用户纠正。

## 现象

执行者在任务清单登记「等待审阅收口授权」「等待降级确认」两条并停止推进，等用户授权。

## 根因

1. 发明了不存在的授权项：退出点列出的授权集合里没有「审阅收口授权」。回归门 rubric 冲突的规则是「停下报使用者裁决」——裁决是呈现事实 + 推荐意见的一次性说明，不是等待授权。
2. 把协议级状态当成任务：待裁决、待确认是协议状态（已停/待确认），不是执行任务，登记进清单就成为永不完成的阻塞项。
3. 降级确认虽然确实只能由用户点名放行，但停下时回复没有按形状呈现（逐条列 pending 降级 + 推荐意见），执行者用「登记待办」替代了「呈现决定」。

## 正确做法

- 授权项是封闭集合，等于退出点已列出的那些，不发明新授权项。
- 命中待裁决 / 待确认时，同轮回复写明事实、推荐意见、需要的一句话决定；不依赖该确认的其余工作按「一轮结束」规则继续。
- 协议级等待不登记进任务清单。
- 降级使完成判据不成立时，按判据停止报诚实结论，不空转等待。
