# Patch Proposal: goal-wait-protocol

- patch_id: 20260929-192710-goal-wait-protocol
- target: skills/task-goal
- mode: update
- risk: medium

## 问题

一次真实执行中，goal 模式的执行者把「等待审阅收口授权」「等待降级确认」登记成任务清单条目并空转等待。规则文本有三个缺口：

1. 授权集合不封闭：退出点列了需要授权的动作，但没说只有这些算授权，执行者发明了不存在的「审阅收口授权」。
2. 「停下等用户确认」「停下报使用者裁决」没有定义停下时回复的形状，执行者只能把等待当任务。
3. 协议级状态（已停、待裁决、待确认）与执行任务没有区分边界，被登记进任务清单成为永不完成的阻塞项。

## 改动

均落在 `skills/task-goal/SKILL.md`：

1. 「授权」节追加：授权项是封闭集合，等于退出点已列出的那些，不发明新授权项；「报使用者裁决」「停下等用户确认」的停下形状是写明事实 + 推荐意见 + 需要的一句话决定；协议级等待是状态不是任务，不登记进任务清单。
2. 退出点「降级未确认」补一句：停止回复逐条列出 `pending` 降级（维度、默认期望、实际交付、偏差理由）并给出「接受 / 不接受」推荐意见；降级使完成判据不成立时按判据停止报诚实结论，不空转等待。

## 理由

封闭授权集合直接消灭「发明授权项」这一失败类；把停下的形状写成可检查的文本（事实 + 推荐 + 一句话决定），让「等待」永远伴随可裁决的表述而非空转；明确「状态不是任务」把任务清单与协议状态分开。三句都复用既有术语（授权、退出点、pending/confirmed、完成判据），不新增概念，与现有门禁不冲突。taskflow 的 pending/confirmed 语义与确认权归属不变——呈现格式归 goal 模式的 task-goal 管，避免第二口径。

## 可验证点

- 退出点「降级未确认」含「给出推荐意见」与「不空转等待」。
- 「协议级等待是状态不是任务，不登记进任务清单」在文中出现一次。
