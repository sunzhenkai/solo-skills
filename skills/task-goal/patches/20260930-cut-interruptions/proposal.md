# Proposal：降低 goal 模式下的假打断（task-goal 侧）

## 背景

goal 模式是全自动执行，停机面被放大：8 个任务级停机条件里 5 个是「另一个 agent 的行为」（评审者未定 / 派不出 / 没有结论 / 审阅不通过 / 交接卡住）。已有 `experience/failures/` 两条全是空转类，其中一条 98 分钟零实现产出（`20260930-goal-stop-autocontinue-spin.md`）。

对照代码定位到 6 处「规则把自己逼停」，本次修掉。

## 决定（本 skill 内 6 处编辑）

1. **无进展轮兜底收窄**（「授权」节）。原：执行中/已交接出现无进展轮一律判协议异常改 `已停`。自动续跑轮本来就不带新输入，会把正常等待误判成协议坏了。改：自动续跑造成的无进展按已停行第 1~2 次处理——只做只读工作，不判异常、不改状态；带用户输入或审阅结论的才判异常。
2. **缺完成判据不再全量重做**（起手节）。原：缺判据即「按自产方案处理，从摸底开始」，代价是一次全量返工。改：由「审阅」派出的评审者按摸底与上游方案给出一条可检查的候选判据，收敛即采纳，前提记一行「判据由审阅补齐」；评审者也给不出才回退。**不采用**「答不出就按推荐判据开工」——那会把单方猜测固化成通过线。
3. **详细设计硬墙给出口**（「不套模板」节）。原：`已停。本流程不做详细设计。` 把需要定接口/骨架的任务原地钉死。改：交 task-explore 的 `design` 阶段（该阶段正为此存在），不原地停等用户改方案。
4. **审阅排队的只读工作去歧义**（审阅节）。原：`或「授权」节列名的只读工作`，未写白名单是什么。改：直接列出（只读环境查证、外部原文取证、证据固化；不写交付代码、不改完成判据与步骤）。
5. **审阅结论跨轮复用**（核对节新增段）。每条 P0/P1 的语义指纹、指向的判据/步骤、本轮结论写入任务运行目录 `goal-review-log.md`（与 state-file 同目录）；下一轮指纹相同且上轮「已消失」的不重派审阅，只重派「仍在」与新增条。降低审阅调用与上下文成本。
6. **重申仍停时给最小解除集**（「授权」节）。suspension.md 已有「最小解除集」排序，正文未引用；补上。
7. **复述生效时写清动作清单**（「授权」节）。原：意图命中即生效、靠下一轮纠正回滚，回滚范围不可判。补：复述时一并写清本轮按此执行的动作清单。
8. **危险操作退出点排除已列放行动作**。配合 task-wizard 新增的「执行前授权清单」：清单内可逆、仓内、非线上动作不算未点名，清单外的仍停。

## 理由

- 1、3、6、7 是纯假停消除，不动任何红线。
- 2 的落点选审阅而非用户，是因为 goal 约定「不向用户列选项」，且把判据交给评审者与「用户在场点」是两个不同的门。
- 5 只复用结论、不降低审阅标准：被复用的是同一份语义指纹，换写法仍算同一条（沿用核对节既有定义）。
