# 外部参照

术语见 [../CONTEXT.md](../CONTEXT.md)。定稿前的一次公开参照，避免闭门造车。

## 何时做

本仓摸底之后、方案定稿之前：

- 档位是复杂，或写到定稿前升到复杂：必做。
- 中等档且涉及选型 / 外部集成 / 协议对接：必做。
- 其余情况（简单档、中等档纯局部改动）：跳过，回到方案正文继续写。

做完后路由按事实重判。没有复杂档典型情况时可以低于初步档位；已经命中复杂档时不得降档。已经记下的外部参照留在前提里。

## 先搜后读

先检索、后读原文。

- 用宿主已有的搜索能力检索公开资料；搜索不限次，读到可对证的**原文**为止。
- 原文 = 公开仓库或上游文档里写下该做法的那一处（官方文档章节、标准条文、上游 Issue/PR、成熟开源实现的对应源码或文档），不是转述。
- 阅读最多两处原文。本仓的代码和文档算摸底；本机其他仓库仅当该项目本身公开时才算外部参照。

来源分级，冲突时写明依据：官方文档 / 标准 / RFC > 上游 Issue / PR / Release Notes > 成熟开源实现 > 权威社区 > 其他。

## 一次尝试

只追最会影响步骤的那一个做法。两个做法分不出主次时，追更没把握的那个，另一个写入假设。

## 写入前提

- 对上原文：写入事实。一句话写出做法，并附上公开出处。做法会改步骤时，改步骤。
- 打不开、没有检索或阅读能力、没有命中、或只有转述：写入假设，写明缺的是什么。方案照常写完。
- 两处原文都对上、做法相反：两条都写入事实，各自附上公开出处。步骤采纳一条，另一条写入坑。没有已查证事实能选定哪条时，这是决策点。

事实和假设仍写在前提里。步骤里写采纳之后的动作。

## 做完

前提里写明这一轮追的是哪一个做法，以及结果落在事实、假设，还是两条相反的事实。然后才定稿。
