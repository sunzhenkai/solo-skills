# 对用户说话（task 系列唯一出处）

taskrail / taskflow 面向用户的话按本文件；落盘产物可以保持结构化。

## 1. 以理解、决策和行动为边界

只展示帮助用户理解现状、判断风险、作出决定或采取行动的信息。第一句说当前最重要的结论、结果或影响，随后只给支撑判断所需的最少证据和下一动作；围绕用户当前要理解或决定的事组织内容，不按内部执行顺序复述过程。

是否同步取决于用户的有效认知是否需要更新，而不是内部环节是否变化。没有新增结果、判断、范围 / 风险或决策需求时，纯路由、记账、INDEX 更新和内部状态迁移不单独汇报。已经表达的信息不重复，长任务只同步最新增量；非停点同步继续执行，不等回复、不构成用户确认。

## 2. 默认摘要，按需展开

默认给结论性摘要；确认、排障、`explain` 或用户追问时，按当前理解和决策需要补充背景、取舍与证据。展开以足以支持本次判断为限，不用完整台账代替回答，也不为覆盖所有场景机械套用字段。

current_ref、status、driver、change id、checkbox 编号、criterion、slice、OpenSpec 等内部词不主动倒给用户；需要解释编排时先转译成影响和行动。文件:行、产物路径和原始输出作为可跳过的细节，只有有助于核实、恢复或落地时才展示。

## 3. 先查资料，能查到的不问

先读代码、配置、文档和历史任务；能查到的不写成假设、不拿去问。用户纠正后先回一手资料重查，再说改了什么与出处。结论和证据分开表达，不确定之处标明把握，不用冗长描述掩盖未知。

## 4. 详略与风险匹配

1. 普通可逆取舍按推荐直接定，**说决定，不提问**：用陈述句带一句理由，不以“要不要 / 你看行吗”收尾。意图、实施方案、approve 等停点按 [confirm-protocol.md](confirm-protocol.md) 等明确回复。
2. 难回头决定单独说，说明决定及理由，详略以用户能判断影响为准；陈述决定不等于获得危险动作授权。已做决定写 decisions.md。
3. 执行中除确认协议停点外，真阻塞才停：删除或迁移数据、改共享配置、线上 / 不可逆 / 对外发送、改完成判据（criterion）、缺凭据或只有用户知道的信息。停时突出影响、已完成部分和需要的外部输入。
4. 同一验证连败两次、同一 P0 / P1 两轮未解、写不出可检查 criterion、意图仍对不上时停止盲试；先按 router 换动作，只有缺外部输入才 blocked。
5. 确认展示以用户足以作出本次决定为限；风险、范围或验证策略变化时呈现新增信息，不重复未变化的背景。
6. 内部记账与调度直接做，不转化为用户问题；没有认知增量时不独立汇报。

### 重大方案人话对齐

大型项目、重大改动或架构调整在动工前对齐方案时，用业务和模块人话讲清以下四件事（不用内部编排词或裸文件路径清单代替方案），再给出明确推荐并等待拍板：

- **现状与目标**：现在的问题/约束是什么，改完后系统会变成什么可观察结果。
- **整体方案**：核心模块、职责边界或数据流如何组织（结构复杂时配简图或分层列表）。
- **关键取舍**：为什么选这条路、放弃了哪些可行方案、换来了什么又接受了什么代价。
- **影响面、节奏与回退**：波及哪些现有能力、分几阶段落地、出问题如何回退。

## 5. 恢复与解释

resume 以恢复用户上下文为目的，说明目标、已验证现状和下一动作；存在阻塞时才补充所需输入。explain 在用户要求理解编排时展开当前环节、跳过 / 重入原因及 worktree / driver 状态，仍按结论到依据组织，不只报字段值。

## 6. 完成通知

完成通知以交付结果和验证结论为主，按用户落地需要说明改动位置与如何合入；内部产物路径只在有助于恢复、合入或审计时给出。不以精简为由省略验证缺口、剩余风险、未完成项、必要授权或难回头决定。

父任务只发一次总完成通知，汇总整体结果和集成验证；子任务完成按增量原则同步。任务归档不单独展开，不自动 push 或清理 worktree。

## 前后对比

- 前：「按内部执行顺序复述过程。」；后：「先说用户需要理解的结论与影响。」
- 前：「每次路由都重复完整背景。」；后：「只同步用户认知增量。」
- 前：「为简洁省略验证缺口。」；后：「默认摘要，同时保留决策所需风险。」
- 前：「写完 design 文档只贴路径或步骤清单就开工。」；后：「大型改动先用人话讲清现状、整体方案、关键取舍与影响面，对齐拍板后再写代码。」
