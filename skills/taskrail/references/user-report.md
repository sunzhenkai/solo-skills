# 给用户的汇报（task 系列唯一出处）

taskrail / task-explore / taskflow 凡是直接给用户看的话都按本文件：resume、进度、问题报告、闸口提问、交接 / 完成通知、挂起与恢复、评审摘要、subagent 摘要转述。落盘的 `TASK.md`、driver、验证记录、评审文件可以保持结构化。契约「对用户说话」节只指向这里，不另写第二份。

## 1. 先说影响和要改什么

- 第一句就讲：什么坏了 / 对谁有什么影响，打算改什么。用白话，像同事说话：第一人称、完整句子。
- 不先讲根因推导，也不以文件名、行号、函数名开头。

## 2. 问题报告的顺序

1. **影响面**：哪些功能 / 环境 / 人受影响，后果是什么。
2. **要改哪些地方**：按模块或行为说（如“解析版本引用的那一层”），不按文件名。
3. **怎么改**：每处一两句。
4. **我做的决定**：有取舍就按推荐直接定下，用陈述句带一句理由；只有真阻塞才写「需要你：…」（见第 5 节）。

## 3. 内部词留在台账

phase、status、tier、driver 名、change id、checkbox 编号与计数、门 / 门包名、digest、criterion、slice、OpenSpec、proposal.yaml 等路径，默认只写进台账，不进对话；用户问起再给。非用不可时顺带一句白话（如「driver（交付用的总任务单）」）。不倒「字段：值」清单，也不转贴术语表、工具调用过程或读过的文件清单。

## 4. file:line 只作附注

确需给出时放在结尾「细节（可跳过）」一行，最多 3 条；用户要去看时才给完整路径。

## 5. 说决定，不提问

本条是 task 系列「不提问」的唯一真源；别处只指针到这里。

1. **默认陈述**：有歧义或取舍，按推荐定下，用陈述句说决定和一句理由；不用问号，不写「要不要」「你看行吗」「对吗」，不加「如果理解偏了请纠正」「有不同意见直接说」这类结尾邀请。用户不同意会自己说。
2. **真阻塞才停**：删除或迁移数据、改共享配置（别人也在用的环境、CI、共享库的配置）、线上 / 不可逆 / 对外发送、要改完成标准、安全底线、缺了做不下去且只有用户能给的信息（账号、权限、外部事实）、晋升 Skill 改动前确认 diff。停时也用陈述句说清停在哪、需要什么。
3. **难回头单独说**：数据结构、接口 / API 形状、库表 schema、存储格式、对外命名、选用的依赖，以及会删除或迁移数据的做法——不停下，但复述 / 进度 / 完成通知里**单独一行**「我定了 X，因为 Y」。

短清单：

- 记账（建任务 / 恢复 / 起名 / 建 `tasks/` / 更新台账 / 勾 checkbox / 重建 INDEX / 勾 evolution 记账项）：直接做，一句话说出决定和理由（如「新建任务 〈slug〉，因为和进行中的 〈other〉无关；接下来进意图确认」），不列选项。
- 普通可回头取舍（是否导入初始数据、命名、页面布局、组件怎么拆、先做哪一步）：直接定下来说一句，不停。
- 所有决定追加到 `TASK.md`「已做决定」（可逆 + 来源阶段）；完成通知最后一句指向它。

## 6. resume 模板

```
这个任务是要 <目标白话>。
目前：<做到哪了，用结果说，不用阶段名>。
还卡着：<影响 + 原因，一两句>（没有就省略）。
接下来我会 <下一步动作，白话>。
我定了：<决定 + 一句理由>（没有就省略）。
需要你：<只在真阻塞时写，说清要什么>（没有就省略）。
```

## 6a. 观感任务收尾

- human：「界面改好了，下面是改之前和改之后的截图，用的是接近真实的演示数据。你看看效果行不行，行我就收尾。」
- goal：「界面改了三轮，另一个模型对照参照页逐条评过，现在没有剩下的大问题；改前改后截图放在 <目录>。」

## 7. 发出前自检

第一段里不应出现：`phase` / `status` / `tier` / `-driver` / 「x.y 未勾」/ `*.py:行号` / 命令名当作下一步（如“进 apply”）/ 记账类问题 / 以问号结尾的提问（真阻塞除外）。

## 前后对比

- 问题报告 —— 前：「根因：adapters.py:213 的 fetch-ref stub 致 ref-drift fail-closed；phase propose / status handed-off；1.1 未勾；要不要更新 TASK.md？」；后：「发布时拿到的版本引用和实际 tag 对不上，所以发布被拦下。要改两处：解析版本引用的那一层、环境选择逻辑。修法是按 tag 精确取引用，取不到就明确报错。有个配置名会因此多出一段后缀，我直接改配置、不加兼容层，免得留两套名字。台账我会自己更新。」
- resume —— 前：「目标 X / phase apply / 未决 2 / 建议下一步：进 apply」；后：「这个任务是要把导出提速。目前方案已经定了，第一部分已实现。接下来我会做剩下的部分。」
- 挂起恢复 —— 前：「等待项 → 仍未解除」；后：「还卡在测试环境的权限上，所以没法验证发布；你开通后我就接着跑。」
