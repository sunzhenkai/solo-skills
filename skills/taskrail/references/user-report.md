# 给用户的汇报（task 系列唯一出处）

taskrail / task-explore / taskflow 凡是直接给用户看的话都按本文件：resume、进度、问题报告、闸口提问、交接 / 完成通知、挂起与恢复、评审摘要、subagent 摘要转述。落盘的 `TASK.md`、driver、验证记录、评审文件可以保持结构化。契约「对用户说话」节只指向这里，不另写第二份。

## 1. 先说影响和要改什么

- 第一句就讲：什么坏了 / 对谁有什么影响，打算改什么。用白话，像同事说话：第一人称、完整句子。
- 不先讲根因推导，也不以文件名、行号、函数名开头。

## 2. 问题报告的顺序

1. **影响面**：哪些功能 / 环境 / 人受影响，后果是什么。
2. **要改哪些地方**：按模块或行为说（如“解析版本引用的那一层”），不按文件名。
3. **怎么改**：每处一两句。
4. **我做的决定**：有取舍就按推荐直接定下，用陈述句带一句理由；只有真阻塞才写「需要你：…」（见第 5 节）。

## 3. 内部词留在台账

phase、status、tier、driver 名、change id、checkbox 编号与计数、门 / 门包名、digest、criterion、slice、OpenSpec、proposal.yaml 等路径，默认只写进台账，不进对话；用户问起再给。非用不可时顺带一句白话（如「driver（交付用的总任务单）」）。不倒「字段：值」清单。

## 4. file:line 只作附注

确需给出时放在结尾「细节（可跳过）」一行，最多 3 条；用户要去看时才给完整路径。

## 5. 说决定，不提问

- 默认不向用户提问。有歧义或取舍，就按推荐定下来，用陈述句说出决定和一句理由，例如「这次先只做页面和数据结构，服务你后面自己加，免得跟还没修好的导入链路绑在一起」。用户不同意会自己说。
- 不用问号收尾，不写「要不要」「你看行吗」「对吗」。
- 只有真阻塞才停：删除或迁移数据、改共享配置（别人也在用的环境、CI、共享库的配置）、线上 / 不可逆 / 对外发送的动作、要改完成标准、碰到安全底线、缺了做不下去且只有用户能给的信息（账号、权限、外部事实），以及晋升 Skill 改动前确认 diff。停的时候也用陈述句：说清停在哪、需要什么，例如「发布到线上这一步我先停下，你说『发布』我再动手」「测试环境的账号我这边没有，拿到后我接着验证，其余部分已经做完」。
- 不停、直接定下来说一句的：普通可回头的取舍，例如拓扑先不导入初始数据、命名、页面布局、组件怎么拆、先做哪一步。
- **难回头的决定**：数据结构、接口 / API 形状、库表 schema、存储格式、对外命名、选用的依赖，以及会删除或迁移数据的做法。这类不停下，但在复述、进度和完成通知里**单独一行**说出来：「我定了 X，因为 Y」，不埋在长句里，方便用户一眼看到并叫停。
- 所有定下的决定（含难回头的）都追加到 `TASK.md`「已做决定」，注明可不可逆和来自哪个阶段；完成通知最后一句指向它，例如「这次一共定了 5 件事，难回头的是接口改成分页返回，全部记在任务记录的『已做决定』里」。
- 不问、自己做完后一句话告知的（记账）：更新 `TASK.md` 的 `phase` / `status` / `updated` / 指针、勾 checkbox、勾 evolution 提案里的记账项（如“提案已写”）、重建 INDEX、把台账里过时的“无”改成实情。

## 6. resume 模板

```
这个任务是要 <目标白话>。
目前：<做到哪了，用结果说，不用阶段名>。
还卡着：<影响 + 原因，一两句>（没有就省略）。
接下来我会 <下一步动作，白话>。
我定了：<决定 + 一句理由>（没有就省略）。
需要你：<只在真阻塞时写，说清要什么>（没有就省略）。
```

## 6a. 观感任务收尾

- human：「界面改好了，下面是改之前和改之后的截图，用的是接近真实的演示数据。你看看效果行不行，行我就收尾。」
- goal：「界面改了三轮，另一个模型对照参照页逐条评过，现在没有剩下的大问题；改前改后截图放在 <目录>。」

## 7. 发出前自检

第一段里不应出现：`phase` / `status` / `tier` / `-driver` / 「x.y 未勾」/ `*.py:行号` / 命令名当作下一步（如“进 apply”）/ 记账类问题 / 以问号结尾的提问（真阻塞除外）。

## 前后对比

- 问题报告 —— 前：「根因：adapters.py:213 的 fetch-ref stub 致 ref-drift fail-closed；phase propose / status handed-off；1.1 未勾；要不要更新 TASK.md？」；后：「发布时拿到的版本引用和实际 tag 对不上，所以发布被拦下。要改两处：解析版本引用的那一层、环境选择逻辑。修法是按 tag 精确取引用，取不到就明确报错。有个配置名会因此多出一段后缀，我直接改配置、不加兼容层，免得留两套名字。台账我会自己更新。」
- resume —— 前：「目标 X / phase apply / 未决 2 / 建议下一步：进 apply」；后：「这个任务是要把导出提速。目前方案已经定了，第一部分已实现。接下来我会做剩下的部分。」
- 挂起恢复 —— 前：「等待项 → 仍未解除」；后：「还卡在测试环境的权限上，所以没法验证发布；你开通后我就接着跑。」
