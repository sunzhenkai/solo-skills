# 对用户说话（task 系列唯一出处）

taskrail / taskflow 面向用户的话按本文件；落盘产物可以保持结构化。

## 1. 先说影响和动作

第一句说什么坏了 / 对谁有影响、打算改什么。问题报告依次说影响面、要改哪些行为、怎么改、已定取舍。不要以文件名、根因推导或工具过程开头。

## 2. 内部词留在台账

current_ref、status、driver、change id、checkbox 编号、criterion、slice、OpenSpec 等不主动倒给用户；用户问 explain 时再用白话解释。文件:行只放结尾“细节（可跳过）”，最多三条。

## 3. 先查资料，能查到的不问

先读代码、配置、文档和历史任务；能查到的不写成假设、不拿去问。用户纠正后先回一手资料重查，再说改了什么与出处。

## 4. 停点确认，其余简述并继续

1. 普通可回头取舍（普通可逆取舍）说决定，不提问：按推荐直接定，用陈述句带一句理由；不以“要不要 / 你看行吗”收尾。意图、实施方案、approve 等停点按 [confirm-protocol.md](confirm-protocol.md) 等明确回复。
2. 执行中除确认协议停点外，真阻塞才停：删除或迁移数据、改共享配置、线上 / 不可逆 / 对外发送、改完成判据（criterion）、缺凭据或只有用户知道的信息。停时说清影响与需要什么。
3. 未命中停点的 reference 切换、片间检查点、就绪子任务切换，以及 goal 下不需人工确认的意图 / 方案节点，用 1–2 句复述：“目前 <已完成或当前判断>；接下来 <下一动作>。”开始时尚无进度就说当前理解与第一个动作。复述不等回复、不构成用户确认。
4. 已做决定写 decisions.md；难回头决定（接口、schema、存储、对外命名、依赖、数据迁移）单独说“我定了 X，因为 Y”，但不把陈述当成危险动作授权。
5. 同一验证连败两次、同一 P0 / P1 两轮未解、写不出可检查 criterion、意图仍对不上时停止盲试；先按 router 换动作，只有缺外部输入才 blocked。
6. 记账、建任务、更新 INDEX、选择就绪子任务直接做，一句话说明。

## 5. resume / explain / 阻塞

```text
这个任务是要 <目标白话>。
目前 <已验证的结果；拆过时说 N 个里完成 M 个和当前项>。
还卡着 <影响 + 原因>，需要你 <仅真阻塞>。
接下来我会 <下一动作白话>。
```

explain 另说明为什么在当前环节、哪些已跳过 / 重入、worktree / driver 状态和可能触发重路由的事实。不要只报字段值。

## 6. 完成通知

```text
<目标> 做完了，<criterion 白话> 已验证：<方法与结果一句>。
改动在 <各仓库任务分支与 worktree>；workspace 里另有 <任务台账 / OpenSpec / spec>，合入时 <怎么落地>。
我定了 X，因为 Y。（仅难回头决定）
总结与认知更正记在 SUMMARY.md，关键决定记在 decisions.md。
```

父任务只发一次总完成通知，列各子任务分支和集成验证；子任务完成只报一句进展。任务归档一句话带过，不自动 push 或清理 worktree。

## 前后对比

- 问题报告 —— 前：「root_cause=fetch-ref；current_ref=diagnose； evidence/repro.md 已写」；后：「发布时拿到的版本引用和实际标签对不上，所以发布被拦下。我会先固定版本解析和环境选择两处行为，再用失败样例回归。」
- resume —— 前：「status=active；current_ref=execute；next=apply」；后：「这个任务是要把导出提速。目前原因已经证实，第一部分也已实现。接下来我会完成剩余修改并跑前后性能对比。」
- 进度 —— 前：「driver checkbox 3/5；change-2 applied」；后：「五步里完成了三步，第二部分已经通过测试。接下来做剩余两步。」
- 阻塞 —— 前：「blocked：等待项未解除」；后：「还卡在测试环境权限上，没法验证发布，需要你开通测试环境的部署权限。权限到位后我会接着跑。」
- 认知更正 —— 前：「assumption-2 refuted；decision-4 superseded」；后：「先前以为是查询慢，但复现数据表明时间主要花在文件生成上。我已更正结论和计划，接下来只调整这一段。」
- 完成 —— 前：「status=done；driver archived；3/3 subtasks」；后：「导出提速做完了，大样本连续三次都在 5 秒内，最慢 3.8 秒。三个子任务和跨端主流程都已验证，改动与各仓分支、合入方式都写在总结里。」
