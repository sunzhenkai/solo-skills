# 质量附录（可选）

只在用户点名质量画像 / 降级分级 / 验收打分，或 full 档交付面广时读。默认完成只看 [done.md](done.md)。

## 各交付类别的验收基准

基准物是标准、契约定稿或冻结基线，不拿外部产品当验收基准（外部参照只作输入）。

| 类别 | 基准 | 可自动化 | 运行态证据 | 评审角色（可选调用） |
|------|------|----------|------------|----------------------|
| Web UI | WCAG 2.2 AA + 交互启发式 + 既有组件库 | 见 [ui-delivery.md](ui-delivery.md) | 同左 | `design` |
| 服务 / 后端 | 接口契约 + 既有错误语义 | 契约测试、类型检查、迁移幂等 | 真实进程启动 + 关键路径含失败路径 | `engineer` |
| 数据 / 口径 | 口径定义 + schema / 血缘 | schema 校验、口径单测 | 受控样本端到端 | `data,engineer` |
| 部署 / 密钥 | 最小权限 + 回滚路径 + 密钥不入仓 | 配置校验、密钥扫描 | 本地或预发演练，不拿生产首验 | `sre` |
| 文档 / Skill | 结构规范 + 契约测试 + 引用完整 | 结构 / 链接校验 | Skill 有决策用例 | `skill` |

## 质量画像（点名时写在 `wizard/plan.md`「质量属性」）

```text
受众与场景: <谁在什么场景完成什么>
规模与运行假设: <人数、并发、数据量、本地 / 共享 / 生产>
主流程: <3-7 条，每条一个入口到一个结束状态>
底线: <每条写成可检查的话 + 验证方式（运行 / 截图 / 测试）>
降级: <比默认期望少交付的项：维度 / 实际选择 / 原因 / 是否缩判据>
```

- 「高质量」「体验好」这类形容词不算底线。某项不适用写「不适用」+ 一句原因。
- 降级看实质：改名成「本期简化」也算。缩判据或交付面的降级 = 改判据，按真阻塞停下等用户；不缩的记进「已做决定」继续做。

## 验收打分（点名时）

先交证据再评；实现者自评只作输入。五维各给 0–3 分与证据：功能闭环、UI/UX、工程质量、与画像一致、证据齐全。任一维 0 分不通过；无未处置 Blocker / Major 才通过。分数与证据写进 driver 验证记录。

## 验证分层

静态门（每次改规则 / 契约后）→ 窄切片（首次实现：挑 1–3 个核心闭环走通真实路径，不用假数据冒充）→ 全链路（收尾跑一次）。失败先归因再动手：规则没写清 → 改 skill（走 `patches/`）；实现写错 → 修代码补回归；验收漏维度 → 补验收标准。修好后只重跑受影响层再跑一次全链路。证据注明对应的提交号或未提交改动摘要，换代码后旧证据作废。
