# diagnose：复现并证明原因

## 目的
把“看似坏了 / 慢了”变成可复现现象、基线和有证据的原因。

## 进入条件
bug、性能退化、 flaky test 或修复后失败的原因尚未证明。

## 跳过条件
原因已由一手证据明确，例如确定的错别字；不得因预计改动小就跳过真实根因不明的问题。

## 所需输入
可观察症状、相关版本 / 环境和 explore 事实。

## 执行方法
1. **先建紧耦合红灯反馈回路（tight & red-capable）**：固定版本、输入和环境，构造一条已实跑、秒级确定、能精准断言用户症状并转红的命令（单测 / HTTP / CLI / 浏览器 / trace 回放 / `git bisect`）；性能任务记录样本、指标与基线。未建出可复现红灯命令前不读代码盲猜根因；确实建不出则停下说明已试范围并请求环境或脱敏样本。
2. **最小化复现并列排序假说**：逐项剥离非承重输入将复现缩到最小（Minimise），再在动手验证前列出 3–5 个带可证伪预测的排序假说（防单假说锚定）；每次只改变一个变量验证，保留命令、结果和反证，原始日志落 evidence。
3. **探针清理与接缝回归锁死**：临时调试日志统一打唯一前缀（如 `[DEBUG-a4f2]`），收尾按前缀 grep 清净；在正确测试接缝（seam）先写修复前失败的回归测试，修复后必须重跑未缩小的原始复现回路确认不再复现。若无合适接缝可锁死该类 bug，把“缺接缝”显式记为架构发现。
4. 同类失败没有新证据时停止盲试，补探索或 grill（高难度排查也可按可选外部 skill `diagnosing-bugs` 的梯度回路清单执行）。
5. 多轮或易发散的根因排查按 `trouble-grill` 的锚点、假设板与四道门执行，记录写本任务 `evidence/diagnose.md`；未安装时按本文件方法执行。

## 产出
`evidence/repro*.md` 或指针、基线、根因证据、回归测试方向；更新 context/current。

## 完成门
现象可复现且原因能解释证据；或明确记录不可复现的边界，并由用户接受对应风险。

## 退出与重入
原因明确回 plan / execute；暴露契约问题转 design；测试修复后仍失败且原因不明可带新证据重入。
