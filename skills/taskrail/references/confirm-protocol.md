# 确认协议（薄）

确认方式与路由、执行方式正交。**继续规则**：已确认的意图、实施方案、交付边界和风险均未变化才继续；任一变化，human 回对应 reference 重新明确确认，goal 按下表审阅。说话方式与非停点同步见 [user-report.md](user-report.md)。

## 停点

| 时机 | human | goal |
|---|---|---|
| 新意图形成，或意图 / criterion 变更 | 复述后停等明确确认；有效 resume 不重停 | 简要复述；需审阅时异源审，收敛继续 |
| 首次 execute 前或实施方案实质变更 | 呈现范围、步骤、验证与回退，停等明确确认；checkbox 进度不重停 | 简要复述后继续；命中 approve 按下行审 |
| 实施中新增仓库 / 依赖、公共契约 / schema / 迁移 / 共享配置，或用未提交改动 | 更新 PLAN 并停等明确确认 | 复述变化继续；命中 approve / 真阻塞仍审或停 |
| decompose 拆为独立分支 / 发布 / 子任务，或改交付顺序 | 呈现 ROADMAP 与依赖，停等明确确认；同任务内部切片不停 | 简要复述 ROADMAP 继续 |
| 接受未修复的 Blocker / Major，或验证不足 / 缩小交付 | 说明未修复项、缺失证据与风险，停等明确接受；修后重验不停 | Blocker / Major 不放行；其余按真阻塞与改判据处理 |
| 大型项目 / 重大改动 / 架构调整，或 router 选中 approve | 按 user-report 人话呈现方案、取舍与回退，停等明确确认；不因分支内可逆或内部切片跳过 | 重大方案首次落定 / 实质变更先停等用户人话确认（原话豁免改异源审）；其余异源审收敛继续 |
| 子任务未超父 ROADMAP 范围和子判据 | 意图、approve 不重复停；PLAN 按子任务自身 confirm_mode（默认继承父，可由 ROADMAP 覆写为 human/goal） | 同左 |
| 用户原话有观感目标 | 评审后给用户看改前 / 改后，认可才完成 | 异源模型审截图并迭代 |
| 普通 reference 切换、片间检查点、就绪子任务之间 | 仅同步用户需要知道的新增信息；纯内部迁移不单独汇报，继续且不等回复 | 同左 |
| 真阻塞 / 危险动作 | 停并说明需要什么 | 同左 |

默认意图确认与实施方案确认是两个独立停点；仅单一明确小改（单仓、无 `design`/`decompose`、改点与验证一步读清）可在首轮合并呈现意图复述与最小计划，用户一次确认即同时生效。未回话不算确认；非停点同步不需要回复、不记确认。单独“继续”不授权删除迁移数据、共享配置、线上 / 不可逆 / 对外发送、改 criterion 等真阻塞；任何审阅都不放行真阻塞。stock OpenSpec 普通停顿由编排者处理，不算额外停点。

## 闸口前自查

criterion 可检查；当前 plan 能走到判据；交付标准无漏 / 越界；ROADMAP 子判据覆盖总判据、依赖无环；重大方案与交付前按 `anti-lazy` 核对决策边界与目标差距。未过先回对应 reference。

## 异源模型审

使用另一个模型（与执行者不同、最好更强），附 criterion、不做、相关 plan / design 与证据。P0 / P1 挡路，P2 不挡；同问题两轮未解按 user-report 停。跨机器 / 跨模型委派可经 `agent-roster`（未装则用宿主异源 subagent）；派不出记录降级自审，不静默宣称通过。观感迭代停止以 `pretty-ui/references/critique.md`「迭代与停止」为准（未装 `pretty-ui` 时最多两轮）。
