# 确认协议（薄）

确认方式与路由、执行方式正交。**继续规则**：只有已确认的意图、实施方案、交付边界和风险都未变化才继续；任一变化，human 回对应 reference 重新明确确认，goal 按本表审阅。闸口只回答放行 / 改后放行 / 停；说话方式与非停点复述见 [user-report.md](user-report.md)。

## 停点

| 时机 | human | goal |
|---|---|---|
| 新意图形成，或意图 / criterion 变更 | 复述后停，等用户明确确认或纠偏；已确认且未失效的 resume 不重停 | 简要复述；需审阅时异源模型审，收敛继续；危险动作本身不放行 |
| 首次 execute 前或实施方案实质变更 | 呈现改动范围、步骤、验证与必要回滚，停等明确确认；checkbox 进度不重停 | 简要复述当前方案并继续；router 选中 approve 时仍按下行审 |
| 实施中新增仓库 / 依赖、公共契约 / schema / 迁移 / 共享配置，或使用未提交改动 | 视为方案或风险变化，更新 PLAN 并停等明确确认 | 简要复述变化并继续；命中 approve / 真阻塞时仍审或停 |
| decompose 将同次交付改为独立分支 / 发布 / 子任务，或改变交付顺序 | 呈现 ROADMAP、交付边界和依赖，停等明确确认；同任务内部切片不停 | 简要复述 ROADMAP 并继续 |
| 接受未修复的 Blocker / Major，或验证不足 / 缩小交付 | 说明未修复项、缺失证据和剩余风险，停等明确接受；修复后重验不停 | Blocker / Major 不放行；其他按真阻塞与判据变更规则处理 |
| router 选中 approve | 停，呈现推荐、取舍与回滚 | 异源模型审，收敛继续 |
| 子任务未超父 ROADMAP 范围和子判据 | 意图、approve 不重复停；PLAN 按上述实施确认规则 | 同左 |
| 用户原话有观感目标 | 评审后给用户看改前 / 改后，认可才完成 | 异源模型审截图并迭代 |
| 普通 reference 切换、片间检查点、就绪子任务之间 | 简要复述已完成、当前判断和下一步，继续且不等回复 | 同左 |
| 真阻塞 / 危险动作 | 停并说明需要什么 | 同左 |

意图确认与实施方案确认是两个独立停点。用户没回话不算确认；非停点复述不需要回复，也不能记为确认。单独“继续”不授权删除迁移数据、共享配置、线上 / 不可逆 / 对外发送、改完成判据（criterion）等真阻塞动作。任何审阅都不放行真阻塞。stock OpenSpec 自带的普通停顿由编排者按 taskflow 规则处理，不算额外停点。

## 闸口前自查

criterion 可检查；当前 plan 能走到判据；交付标准无漏 / 越界；ROADMAP 子判据覆盖总判据、依赖无环。未过先回对应 reference，不拿审批代替事实。

## 异源模型审

使用另一个模型，且与执行者不同、最好更强；随附 criterion、不做、相关 plan / design 和必要证据。意图审附用户原话与纠偏，方案审看可检查性、可行性、范围和回滚。P0 / P1 挡路，P2 不挡；同一问题两轮未解按 user-report 停。派不出时明确记录原因和降级自审，不静默宣称异源通过。观感迭代的轮次与停止以 [critique.md](../../pretty-ui/references/critique.md)「迭代与停止」为准。
