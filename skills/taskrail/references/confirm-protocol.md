# 确认协议（薄）

确认方式与路由、执行方式正交。闸口只回答放行 / 改后放行 / 停；说话方式见 [user-report.md](user-report.md)。

## 停点

| 时机 | human | goal |
|---|---|---|
| 意图或 criterion 需要确认 / 变更 | 停，等用户确认或纠偏 | 异源模型审，收敛继续；危险动作本身不放行 |
| router 选中 approve | 停，呈现推荐、取舍与回滚 | 异源模型审，收敛继续 |
| 子任务未超父 ROADMAP 范围和子判据 | 不单独停 | 同左 |
| 用户原话有观感目标 | 评审后给用户看改前 / 改后，认可才完成 | 异源模型审截图并迭代 |
| 普通 reference 切换、片间检查点、就绪子任务之间 | 说决定继续 | 同左 |
| 真阻塞 / 危险动作 | 停并说明需要什么 | 同左 |

用户没回话不算确认；单独“继续”不授权删除迁移数据、共享配置、线上 / 不可逆 / 对外发送、改完成判据（criterion）等真阻塞动作。任何审阅都不放行真阻塞。stock OpenSpec 自带的普通停顿由编排者按 taskflow 规则处理，不算额外停点。

## 闸口前自查

criterion 可检查；当前 plan 能走到判据；交付标准无漏 / 越界；ROADMAP 子判据覆盖总判据、依赖无环。未过先回对应 reference，不拿审批代替事实。

## 异源模型审

使用另一个模型，且与执行者不同、最好更强；随附 criterion、不做、相关 plan / design 和必要证据。意图审附用户原话与纠偏，方案审看可检查性、可行性、范围和回滚。P0 / P1 挡路，P2 不挡；同一问题两轮未解按 user-report 停。派不出时明确记录原因和降级自审，不静默宣称异源通过。观感迭代的轮次与停止以 [critique.md](../../pretty-ui/references/critique.md)「迭代与停止」为准。
