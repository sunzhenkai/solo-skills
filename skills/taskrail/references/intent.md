# intent：目标、约束与完成判据

先对齐要干嘛、输出什么、怎样算完成。详细代码摸底属于 [explore.md](explore.md)，不在意图阶段全仓扫描。

## 先定做多少

- 原话已说清改什么、怎么算完成：只读必要目标处，给一两句复述并写 criterion。
- resume 已有 confirmed / assumed 意图且未失效：沿用，不重做。
- 子任务继承父意图与 ROADMAP 自己那一行，不重新确认；超出子判据才回 intent。
- 纯问答直接回答，不建任务。

## 注意任务边界与读资料顺序

先推词义，再确定改动边界；默认只覆盖目标加它的直接依赖，不把“顺便优化”扩进任务。读资料的顺序是用户原话与纠偏 → 已有 TASK / intent → workspace 与目标项目说明 → 必要代码或配置；能从一手资料查到的不问，详细全仓探索留给 explore。

## 流程

1. 按上述顺序读取，只取理解目标和判据所需内容。
2. 用 1–3 句第一人称口语说明做什么、产出落在哪、接下来怎样；决定与假设写 decisions / context，不逐字段打印。需要用户纠偏时说“理解偏了请纠正”，但不把它当成每个普通步骤的固定尾问。
3. human 下需要确认时按 [confirm-protocol.md](confirm-protocol.md) 停；goal 下按同一协议审。用户没回话不算确认。
4. 把结构化意图写 `context/current.md`，criterion 原文写 TASK，当前最小步骤由 [plan.md](plan.md) 负责。

## 覆盖清单
- 要干嘛：<目标>；为什么：<原因>
- 怎么干：<当前方法或计划指针，不提前展开详细步骤>
- 输出什么：<交付物与落点>；做完的样子：<可检查标准>
- 上下文：<现状、约束、已有工作与证据指针>
- 不做：<用户原话中的限制>
- 我的假设：<假设与把握高低>
- 我的决定：<决定与一句理由；没有写“无”>
- 需要你提供的：<只限真阻塞；没有写“无”>

内部自查与 `context/current.md` 的结构化意图使用以上字段，不对用户逐项打印。宽泛目标保持宽泛；“不做”只来自用户原话，自加限制写入假设；详细实现步骤由 plan 负责。

## 纠偏与变更

- 用户指出错误先回一手资料重查，只改受影响结论并给出处；同一错误不重犯。
- 多轮对不上时并排两种理解和各自证据；仍缺只有用户知道的信息才真阻塞。
- criterion 必须可检查；性能写样本 / 指标，观感写参照与验收方式，不能用“高质量”代替。
- 中途变更按 [contract.md](contract.md)「意图与认知变更」：更新 criterion、标旧认知 refuted / superseded，只使受影响产物失效。
- 难逆或危险动作本身仍在执行前按 [user-report.md](user-report.md) 停，意图审阅不构成授权。
