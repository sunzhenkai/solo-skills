# 增量维护与自愈

## 变更路由

先运行 `status`，再按下表决定阅读范围。一个改动可命中多页，但不按文件机械建页。

| 代码变化 | 复核内容 |
|---|---|
| 状态、分支、补偿、业务规则 | 所属 L2、对应 L1 核心流程；必要时更新 L0 主链路 |
| 对外接口、消息、权限、邻接系统 | 领域边界、相关时序图和异常路径 |
| 实体、存储、事务、一致性 | 核心实体、数据流、失败与补偿规则 |
| 仅实现重构且外部行为不变 | 核对映射页的语义；确认无内容变化后 `verify` |
| 新模块未进入 Atlas | 按主链路价值并入现有 L1/L2，或增加最小下钻页 |

`stale` 是计算状态，不手写到 frontmatter。`source_digest` 不一致表示需要复核；`missing_sources` 表示映射已失效，先调整路径再复核。每轮只处理 `stale_pages` 与当前需求涉及的页面，无需重写整个 Atlas。

## 复核顺序

1. 读取页面全文和当前 `sources`，保留仍成立的人工说明。
2. 沿代码调用链核实主路径、关键分支和失败结果；没有证据的内容标为草稿或删除。
3. 更新当前页，再检查上级摘要和同级交叉链接是否仍成立。
4. 对本轮页面运行 `verify`，随后运行 `build` 和 `check`。`check` 将断链、跨层缺链、缺失映射和过期页列为错误。

## 图与静态文件

静态资源统一放 `assets/`：

- 架构图、流程图、状态图优先生成可缩放的 SVG；需要交互时使用自包含 HTML。
- 独立 HTML 的 `href` / `src` 也使用 Atlas 内相对路径。构建时会检查目标并改写其中的 `.md` 链接。
- 图的标题和正文使用与页面相同的领域术语；图旁写一句阅读重点和对应业务页链接。
- 删除或移动资源后运行 `check`，修复所有引用。构建会复制全部 `assets/`，因此保留仍能支持理解的资源。

`_site/` 全部由 `build` 重建，直接编辑只会被下一次构建覆盖。需要改内容时编辑 Markdown 或 `assets/` 真源。

## 完成门

- `build` 成功，`_site/index.html` 能作为入口离线打开。
- `check.ok=true`，`stale_pages=[]`，没有断链或缺失的上级/下级导航。
- 本轮涉及的复杂逻辑图与文字一致，静态 HTML 中的 Markdown 链接已生成对应 HTML 跳转。
- 未覆盖范围仍标 `draft`，回执明确说明，避免把局部覆盖描述成全量覆盖。
