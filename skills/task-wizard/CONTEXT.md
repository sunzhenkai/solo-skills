# Task Wizard

把一句任务描述拆成步骤级、可移交的方案，交给人或下游执行方（task-goal / task-explore / task-delivery）。

## Language

**任务方案**:
写给人或下游执行方的步骤级纲要。产出后本 skill 停下，不执行。处在 goal 里时由 task-goal 接走并接管确认与审阅。
_Avoid_: Goal 方案, Plan, objective

**完成判据**:
方案「目标」里那条可检查的话，用来判断这份方案是否做完。
_Avoid_: 目标, objective, 交付标准

**交付标准**:
完成判据之外、本任务应有的交付面要求，每条可检查。只取验证或测试覆盖、错误与边界行为、文档与配置等配套更新里与本任务相关的几条；没有就写「无」。
_Avoid_: 完成判据, 详细设计, 质量目标

**阻塞点**:
会卡住整份方案、需要先解开的前提。
_Avoid_: 坑

**决策收敛**:
方案落稿前把所有要人拍板的缺口（歧义、假设、阻塞点、执行中须授权的动作）写进方案。下游只做「按此执行 / 调整哪步 / 改路由」三选一，方案外缺口不允许在执行期冒出来向人要答案。
_Avoid_: 执行中再确认, 边走边问

**复杂度档位**:
任务走哪条衔接，只取简单、中等、复杂，对应复杂度低、中、高。简单通常是局部修改。中等通常是一个中等需求，可以跨多个模块或仓库，改动量稍大或逻辑稍微复杂。复杂是项目级重构、逻辑重塑，或业务逻辑复杂且涉及面广。命中复杂的任一条即复杂。
_Avoid_: 完成程度, 方案置信度

**外部参照**:
为补方案读到的一条公开做法，出处是检索、开源实现或上游文档。对上原始出处的记为事实，对不上的记为假设。只在复杂档、方案定稿前做一次。
_Avoid_: 参考, 参考步骤, 建议, 参考意见

**闭门造车**:
复杂档里会改步骤的做法，定稿前没有尝试外部参照。
_Avoid_: 没调研, 调研不足
