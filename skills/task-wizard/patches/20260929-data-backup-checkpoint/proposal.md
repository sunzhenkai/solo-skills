# Proposal：task-wizard 加数据备份检查点与「风险点」小节

## 背景

任务涉及数据写、删、迁移、改库表结构时，备份与回滚路径必须在方案阶段显式评估。大 size 数据难以备份、或操作不可回滚的高风险项，不能藏在「坑 / 注意事项」里被略读，要单独成节强制面对。

## 改动

- 工作流新增第 3 步「数据备份检查点」：涉及数据写删改时先判断备份方式与回滚路径，写进「前提」或「步骤」；难以备份或不可回滚的必须写进「风险点」。**回滚语义限定为本次任务改动**：出问题时能快速回到改动前状态，不要求全量历史回溯。
- 输出模板在「坑 / 注意事项」后新增「## 风险点」小节，明确列出大 size 数据难备份、本次改动不可回滚等高风险项；无则写「无」，不许省略。
- 后续步骤编号顺延（外部参照 → 4、产出方案 → 5、对齐 → 6）。
- 契约测试新增 `TestDataBackupCheckpoint` 类 3 条断言。

## 不做

- 不强制每步都写备份动作（只在涉及数据写删改时触发评估）。
- 不动「坑 / 注意事项」既有语义，授权动作仍归那里。

## 验证

`python3 -m pytest skills/task-wizard/tests -q` 全过；全仓 pytest 全过。
