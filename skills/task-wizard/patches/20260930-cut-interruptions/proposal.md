# Proposal：待授权动作分两张清单（task-wizard 侧）

## 背景

goal 模式下「凡确认走审阅」把每一步的授权都变成一次停机；而 wizard 现行「决策收敛」只笼统写「执行中必须停下来要授权的动作（写入「坑 / 注意事项」标注）」，没有区分「不可逆/线上」与「可逆、仓内、非线上」两类。结果是执行期每一次授权都成一次打断。

## 决定

「决策收敛」节把待授权动作分成两张清单写入「坑 / 注意事项」：

- **①需逐步授权**：线上动作、泄密风险、破坏性 git、删除或不可逆改写、改密钥或权限、对外发送、不可逆迁移。始终要用户逐步点名，不在方案阶段执行。
- **②执行前授权清单**：为走完本次步骤需要一次性放行的**可逆、仓内、非线上**动作。用户对方案的接受即视为已放行；未列进②的动作一律按①处理。

封闭列举，不给判断标准——「可逆、仓内」的判断若留给执行者，会稀释「未点名的危险操作」退出点。

配套：task-goal 的退出点「未点名的危险操作」同步加一句「上游方案的执行前授权清单里列明的动作不算未点名，清单外的仍停」（见 task-goal 侧 patch）。

## 理由

- 线上动作与 A 类降级确认**结构性不可前移**（task-goal 退出点原文：线上动作「任务描述里写过也停」；A 类降级「审阅收敛与单独的继续都不算确认」），所以本改动**只**减「未点名危险操作」这一类打断，不承诺更多。
- ②的放行来自用户对方案的接受，是一次真实的用户动作，不是 agent 自行推断。

## 验证

- 契约测试：`python3 -m pytest skills/task-wizard -q` 全过（本改动为陈述句，无既有断言覆盖该措辞）。
- 与 task-goal 侧同批应用；单独应用会使①/②清单与 goal 退出点冲突。

## 明确不改

复杂度路由表、外部参照触发范围、输出模板小节、边界节「线上步骤标注需逐步授权」。
