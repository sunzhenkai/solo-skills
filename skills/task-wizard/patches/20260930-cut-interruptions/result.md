# Result：待授权动作分两张清单

已 `git apply` 应用。「决策收敛」节现在把待授权动作分成①需逐步授权 / ②执行前授权清单两类写入「坑 / 注意事项」。

## 应用后的正文变化

①**需逐步授权**：线上动作、泄密风险、破坏性 git、删除或不可逆改写、改密钥或权限、对外发送、不可逆迁移——始终逐字点名，不在方案阶段执行。
②**执行前授权清单**：为走完本次步骤需一次性放行的可逆、仓内、非线上动作——用户对方案的接受即视为已放行；未列进②的一律按①处理。

封闭列举，未给判断标准（避免执行者自行裁量「可逆、仓内」而稀释危险操作退出点）。

## 遗留

- 配套改动在 task-goal 侧：「未点名的危险操作」退出点已加「上游方案的执行前授权清单里列明的动作不算未点名，清单外的仍停」。两者必须同批存在，单独应用会使①/②清单与 goal 退出点冲突。

## 未验证 / 待观察

「用户对方案的接受即视为已放行」的实际边界：若方案里②清单写得过宽，会实质架空「未点名的危险操作」退出点。需在后续运行中观察②清单的规模，过宽时收紧为更细的封闭列举。
