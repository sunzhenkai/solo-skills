# 设计体系（刻度与 token）

[pretty-ui](../SKILL.md) 的 system 模式、build 第 4 步、补 token 时读本页。体系的作用是把每一次取值变成“从刻度里挑”，而不是每次凭感觉；同一个页面里出现第三个相近却不同的间距值，就是缺刻度的信号。token 与组件统一的 init / audit、迁移与验证按 [engineering.md](engineering.md)。

## 1. 先盘点，再补缺

动手前在项目里找已有的体系：`tokens.css`、CSS 变量、Tailwind 配置、主题文件、组件库、品牌规范、`DESIGN.md`。按下面 12 项列出“已有 / 部分 / 缺”：

| 体系 | 内容 |
| --- | --- |
| 颜色 | 品牌色阶、灰阶、语义色（成功、警告、危险、信息）、暗色模式映射 |
| 字体 | 字族与回退、字阶、字重、行高、字距 |
| 间距 | 间距刻度、组件内边距、区块间距 |
| 布局 | 容器宽度、栅格、断点、正文行宽 |
| 圆角 | 一个统一的决定，加少量层级 |
| 深度 | 阴影层级、层叠顺序、遮罩 |
| 边框 | 粗细、颜色、什么时候用边框而不是间距或底色 |
| 图标 | 图标集、尺寸、描边粗细 |
| 控件 | 按钮层级、输入框、选中、标签、开关的共用形状与状态 |
| 状态 | 悬停、按下、聚焦、禁用、加载、空、出错 |
| 动效 | 时长、缓动、哪些属性可以动 |
| 语气 | 按钮文案、提示、错误信息的写法 |

已有的部分原样沿用，命名跟随项目；只补缺的刻度，并在 `DESIGN.md` 里写清哪些是新增的。

## 2. 缺项自定

缺的项较多、又没有品牌规范时，按方向卡自定主色来源（已有品牌色、参考产品或方向卡）、调性（安静 ↔ 喧闹、疏 ↔ 密、活泼 ↔ 庄重）和是否做暗色模式，在 `DESIGN.md` 用陈述句写下决定与理由，接着生成。

## 3. 颜色

### 3.1 色阶

- 每个色相一条 9 级色阶（100–900，需要时加 50 和 950）。品牌主色、灰阶、每个语义色各一条；装饰色按需再加。
- 用 `scripts/palette.py` 生成，主色放在 500：

```bash
python3 scripts/palette.py --base '#0f7b6c' --name brand --css     # 输出 CSS 变量
python3 scripts/palette.py --grey --temperature cool --css          # 冷灰阶
python3 scripts/palette.py --base '#d97706' --name warning --json   # JSON 结构
```

- 算法：先定 500 和两端（100 最浅、900 最深），再二分出 700 / 300，再二分出 800 / 600 / 400 / 200；明度离 50% 越远饱和度越高，避免两端发灰；变浅时色相向亮色相（黄、青、品红）转、变深时向暗色相（红、绿、蓝）转，转动上限 20°，超过 30° 会读成另一种颜色。
- 灰阶带温度：冷灰偏蓝、暖灰偏黄，与主色的冷暖一致；最浅一级停在接近白而不是纯白。
- 生成后在真实界面里看：黄、青这类亮色相的 500 往往显得太浅，按眼睛调整，而不是死守算法输出。
- 主色本身很深（明度低于约 30%）时调低 `--darkest`（如 12），让 900 仍比 500 深；语义色的浅底（50、100）容易漂到邻近色相（红变桃、绿变青），用较小的 `--cap` 或按眼睛挑一个，再用对比度脚本量过。

### 3.2 对比度

- 只校验界面里真实出现的文字 / 背景配对，用 `scripts/contrast.py`：

```bash
python3 scripts/contrast.py --pair '#6b7280' '#ffffff'
python3 scripts/contrast.py --pair '#ffffff' '#0f7b6c' --size large
python3 scripts/contrast.py --matrix pairs.json   # {"pairs": [{"name": "正文", "fg": "#…", "bg": "#…", "size": "normal"}]}
```

- 门槛：正文至少 4.5:1，18px 以上或 14px 粗体以上的大字至少 3:1；图标、输入框边框等非文字元素至少 3:1。
- 不达标时两种修法优先：**翻转**（深色有色底上的浅字，改成同色浅底上的深色字），或**转色相**（文字色相向青、品红、黄转一点，在不变白的前提下提高对比）。

### 3.3 语义与用量

- 语义色只表达状态：危险、警告、成功、信息各有固定含义，同时配文字或图标。
- 强调色有预算，常规界面约占画面一成；主操作、当前选中、关键数字用它，其余交给灰阶。
- 有色底上的次要文字用同色相的浅一级或深一级，而不是灰色或半透明白。

## 4. 字体

- **字阶**（px）：12、14、16、18、20、24、30、36、48、60、72。13 只给密集工具的辅助文字。展示字号之间跳得开，正文附近的级差小。
- **字重**：正文 400 或 500，强调 600 或 700，两档足够；低于 400 的字重只给大展示字。
- **行高**：中文正文 1.6–1.75，英文正文 1.5–1.6；标题随字号变大而收紧，多行中文标题 1.2–1.35，大展示字 1.1–1.2。
- **字距**：大标题略收紧，全大写的英文小标签放宽约 0.05em；中文正文保持默认字距。
- **字族**：系统字体栈是可靠的默认，中文回退写全；现成写法取 [assets/reading-page.html](../assets/reading-page.html) 顶部的 `--font-sans`、`--font-serif`、`--font-mono`，只维护那一份。
- 方向卡指定了字体时，按需引入并保留上述回退；离线交付的页面只用系统字体或随包附带的字体文件。
- 数字列和会跳动的数字用等宽数字（`font-variant-numeric: tabular-nums`）。

## 5. 间距、布局、圆角、深度、边框

- **间距刻度**（px）：4、8、12、16、24、32、48、64、96、128。从多到少：先给足留白，再按需要收紧。
- **分组**：组内间距小于组间间距，相邻两级至少差一档；标签与控件之间的距离小于控件与下一组之间的距离。
- **布局**：内容决定宽度，而不是“铺满屏幕”；表单、卡片、正文各有自己的最大宽度。正文行长按 rules.md 的 T2，列宽 = 字号 × 字数，用 `px` 或 `rem` 写在正文列上；宽表格和图解可以更宽。
- **圆角**：全局一个决定（方、微圆、圆），再分出小控件、卡片、浮层两三级；同一层级的元素圆角一致。
- **阴影**（五级就够，先定最小和最大，中间大致线性填）：

```css
--shadow-1: 0 1px 3px rgb(0 0 0 / .2);
--shadow-2: 0 4px 6px rgb(0 0 0 / .2);
--shadow-3: 0 5px 15px rgb(0 0 0 / .2);
--shadow-4: 0 10px 24px rgb(0 0 0 / .2);
--shadow-5: 0 15px 35px rgb(0 0 0 / .2);
```

  阴影表达离用户多近：按钮 1 级、下拉菜单 3 级、模态框 5 级，按层级选而不是按好看选。光源来自上方，阴影只向下偏移、不横向偏移。需要更细腻时用两段阴影，一段紧贴的接触阴影、一段大而柔的环境阴影，层级越高接触阴影越淡。凸起元素的上沿用手挑的浅一级颜色，而不是叠半透明白。暗色模式里深度靠表面明度区分（越高的层越亮），阴影退居其次。
- **边框**：1px 和 2px 两档。分隔优先用间距和底色差，边框留给输入框和需要明确边界的地方。

## 6. 两层 token

- **基础层**：原始刻度，如 `--color-brand-600`、`--space-4`、`--text-16`。
- **语义层**：表达用途，引用基础层；组件只用语义层，这样暗色模式和换品牌只是重新映射。

语义层最小集合：

```css
:root {
  --surface: …;  --surface-raised: …;  --surface-sunken: …;
  --text: …;  --text-secondary: …;  --text-muted: …;
  --border: …;  --border-strong: …;
  --action: …;  --action-hover: …;  --action-subtle: …;
  --danger: …;  --warning: …;  --success: …;  --info: …;
}
```

- **暗色模式**：重新映射语义层，而不是把颜色取反；表面从深灰起步而不是纯黑，文字用接近白的浅灰；有色元素降低饱和度、调整明度后重新校验对比度。

## 7. 产出

| 文件 | 内容 |
| --- | --- |
| `tokens.css` | 基础层与语义层的 CSS 变量；暗色模式用 `[data-theme="dark"]` 或 `prefers-color-scheme` 覆盖语义层 |
| `DESIGN.md` | 方向卡摘要、每个刻度的取值与理由、哪些沿用项目既有、哪些新增、对比度校验结果、使用规则（什么时候用哪一级） |
| `preview.html` | 一页看全体系：色阶、字阶样张（含中文）、间距、圆角、阴影、按钮与输入框的各个状态；离线可打开 |

三个文件放在项目约定的位置；没有约定时放 `design-system/`。preview 页面同样跑 `scripts/check_page.py` 并截图看一眼。

在 taskrail 任务里，这三个文件就是 Active Instance 的内容；版本目录、freeze 与摘要规则按 taskrail 的 `ui-delivery.md` 执行。
