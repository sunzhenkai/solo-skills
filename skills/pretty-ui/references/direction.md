# 设计方向（天花板）

[pretty-ui](../SKILL.md) build 第 3 步、page 的轻量方向卡、上游流程要求“写视觉方向”时读本页。

方向要达到的程度：这个品类里最好的团队会这样做，而且做出了这个产品自己的样子。只是“和模型平时做的不一样”还不够；辨识度来自一套语言的完整和细节，而不是题材少见。方向里的题材、材质、字体和配色，每次都从当前产品的内容、受众和使用场合里推出；撞上常见的流行风格时，要说得出它来自这个产品的理由，说不出就重选。

## 1. 认品类，拆标杆

1. **说出品类和标杆**：这是什么品类（如“项目管理工具”“作品画廊”“事故复盘文档”），这个品类里风格最鲜明的两三家是谁。
2. **对着真实画面拆**：用浏览器或搜索取到标杆的首屏和一个关键控件的截图，存进任务目录再拆，记忆里的产品常常是它几年前的样子。拆成 6–10 条看得见的要素，每条写“它是什么样”和“为什么这样做”，覆盖控件形状与手感、字体、颜色、图标、状态反馈、动效、文案语气、首屏放了什么。拆出来只有“干净、留白、一种强调色”说明没拆到位。确实拿不到画面时，在方向卡“标杆与取舍”开头写“未看图，凭记忆”，并把字体、色彩、主视觉三栏标为待验证。
3. **决定留什么、换什么**：拿本产品的受众、内容和场合逐条对照，理由同样成立的留下，不成立的换掉，换掉的部分由生成引擎给出替代。

拆的时候分清三样东西：

- **基线**：用户已经习惯的结构（画廊作品先行、商店购物车在右上角、后台有侧栏）。沿用它，用户不用重新学。
- **套路**：这个品类人人都用的默认版式。一轮方向里至少有一个要打破它。
- **撞脸**：字体、配色、主视觉和图标都和某个标杆一样，只换了名字。任何方向都要避开。

## 2. 调性五刻度

从题材、受众、品牌语气和使用场合推出调性，每个刻度写出取值和依据：

| 刻度 | 两端 | 在画面上看什么 |
| --- | --- | --- |
| 能量 | 安静 ↔ 喧闹 | 饱和度、对比、元素是否碰撞 |
| 完成度 | 粗粝 ↔ 精致 | 边缘处理、颗粒与噪点、对齐是否严格 |
| 密度 | 疏 ↔ 密 | 留白尺度、叠层、网格纪律 |
| 分量 | 轻 ↔ 重 | 字重、色块面积、阴影硬度 |
| 严肃度 | 活泼 ↔ 庄重 | 圆角、插画语言、动效幅度 |

任何组合都可以成立，失败的是没有依据的默认。最常见的失败：证据指向喧闹粗粝，交付的却是米色卡片、柔和阴影和大留白，被磨回了模型默认的“安静高级”。反过来，给本该安静的产品硬加颗粒和粗边框，同样是失败。证据已经锁定调性时，候选都留在这个调性里，在构图、色彩和主视觉上拉开。

### 模糊词先翻译

“高级、精致、克制、大气、有设计感、简洁”不能当设计理由，用户或自己说出这类词时，先翻译成看得见的决定：

| 模糊词 | 翻译成什么 |
| --- | --- |
| 高级 | 先说是哪一种高级，再定字体对比、分隔方式、间距尺度和色相数量 |
| 精致 | 公差：字距怎么调、对齐到几像素的网格、阴影最多几级、色相最多几种 |
| 克制 | 预算：强调色不超过画面约 10%，动效幅度上限，色相数量上限 |
| 大气 / 有冲击力 | 尺度：展示字多大、主图占多少面积、明暗对比多强；首屏只有一个主角 |
| 简洁 | 密度档位，以及删掉什么、为什么删 |
| 有设计感 | 哪一处做到了品类里少见的完成度：一个记忆点，加上全页一致的控件语法 |

翻译不出看得见的决定的词，从理由里删掉。

## 3. 用生成引擎起方向

每个方向从一个具体的引擎出发，不同方向最好用不同的引擎；引擎的内容来自产品的证据。

- **材质 × 环境**：一种材质放在一个具体环境里，由它推出光照、深度、边缘处理和动效阻尼。
- **一个具体场景**：有时间、地点和光线的场景，由它推出质感和节奏。
- **角色原型**：给产品一个具体性格，让性格决定字体和动作。
- **设计运动或文化语法**：选一个和题材、受众或地域有真实联系的视觉传统，借它的语法，而不是贴它的图案。
- **借另一个领域的表现形式**：只借最有辨识度的一两个手法，页面仍是原来的体裁，避免把道具一件件搬进来。
- **有意打破常规**：激进的非对称、不和谐的配色与字体，但整体仍好看、功能完整。

引擎决定结构、手感、质感和动效；颜色按下一节单独定。

## 4. 定色彩

颜色的第一来源是产品自己的品牌资产、实物和内容画面。没有现成主色时，避免直接拿引擎里材质或场景的固有色当主色，否则不同产品会撞进同一组颜色。按三步定：

1. 写下品类最顺手的默认配色（底色 + 强调色），以及标杆各占了哪个色相和明暗。
2. 每个方向定一套不同的色相家族或明确的黑白，用一句话写它来自产品的什么（内容、受众或品牌）。避开刚拆过的标杆配色；至少一个方向跳出品类默认配色。
3. 写出至少三层：底色、主强调色，以及由它们派生的选中底、描边和禁用态。色阶按 [system.md](system.md) 生成。

黑白灰加一种强调色、甚至完全不用彩色，也是完整的色彩身份，这时颜色交给内容。方向之间按色相家族或材质区分，明暗只是结果；“一个亮、一个暗、一个暖”是最典型的伪差异。

## 5. 首屏骨架

写文案之前先定骨架，先回答：用户来首屏是看什么、做什么？

- **来看内容、挑东西或处理对象的页面**（文档、画廊、商店、信息流、工具、后台）：首屏就是第一排内容或工作区。导航、标题和筛选合起来不超过一两行，第一排内容完整出现在首屏，不放口号和“这个页面是干什么的”段落。浏览就让内容铺满，处理就让当前对象和动作挨在一起，详情按需展开。
- **来被说服的页面**（落地页、品牌页、发布页）：首屏是一个论点。可选的骨架有大字排版、满版主视觉、产品实物特写、可操作的演示、对比前后、数字即主角、叙事开场、清单式陈列等；左右分栏是模型的默认答案，只在确有理由时用。介绍产品时让用户看到产品真正交付的东西（一份生成好的报表、一段处理后的数据），胜过文字承诺。
- **两种都有**：以用户最常来做的事为准，横幅不能把第一排内容推出首屏。

## 6. 方向卡

每项都填具体选择，不填形容词：

| 栏目 | 写到什么程度 |
| --- | --- |
| 北极星 | 一句能指导取舍的意图：第一感受是什么，整页围绕什么展开 |
| 调性 | 五个刻度的取值与依据 |
| 标杆与取舍 | 品类、拆了哪几家、截图存放路径（或“未看图，凭记忆”）；沿用了什么、换掉了什么、为什么 |
| 生成引擎 | 哪一种、具体是什么、来自产品的什么证据 |
| 首屏骨架 | 用户来首屏看什么；内容页写首屏能看到几个对象、页头占几行；说服型页面写选了哪种骨架，附 3–5 个方框的线框 |
| 页面结构 | 首屏以下怎么组织，各主要区块长成什么形式 |
| 字体 | 具体字族、字重和尺度关系：展示、正文、数据各用什么，相差多大；中文回退字体是什么 |
| 色彩 | 十六进制色值与用途，至少三层，加一句来源 |
| 主视觉 | 哪张图或哪个图形承担情绪与识别，来自复用、生成还是排版本身 |
| 图标 | 用哪一套、描边粗细与端点，或者改用字符和编号 |
| 控件语法 | 按钮、输入、选中、标签、状态共用的形状和手感，一句话写清：圆角多大、描边多粗、按下怎样变化 |
| 动效 | 手感用“一个拟声词 + 一个实物动作”写；三处基本动效各怎么动 |
| 记忆点 | 集中发力的一两处：在哪个时刻或位置，用什么材质、动作或画法 |
| 放弃什么 | 这个方向主动不要的常见做法 |

**两遍法**：方向卡写完、动手之前，拿它和“任何类似页面你都会给出的默认答案”对一遍；读起来像默认答案的栏目就改，并写下改了什么、为什么。确认之后严格按卡实现，每个颜色和字体决定都从卡里来。

**轻量方向卡**（page 模式、小范围改版、上游计划里的“视觉方向”）：只写北极星、字体、色彩三层与来源、一个特征元素，再列几件参照（作品或既有页面，写清取它哪一点）和放弃什么。

## 7. 差异检验

方向卡写完、做首屏之前逐条过（用户给了品牌规范或在选定方向上派生版式时，字体与色彩共用，其余几条照样过）：

- **比线框，不比描述**：各方向的首屏线框并排比；描述各不相同、线框都是“左大标题右小块”，就是同一骨架。
- **四项至多一项相同**：首屏骨架、字体、色彩、主视觉四项里，任意两个方向至多一项相同。
- **至少一个走到极端**：在证据允许的调性内，至少一个方向在构图、色彩和主视觉上都做明确选择；折中的方向至多一个。
- **至少一个打破品类套路**：后台的“侧栏 + 顶栏 + 卡片网格”、落地页的“主视觉 + 特性 + 评价 + 按钮”、AI 与开发者工具的“黑底 + 紫蓝光晕 + 粒子”等。打破套路不等于抛弃基线。
- **避开 AI 默认样貌**：对照 [rules.md](rules.md) 的 X 组；品牌或用户明确要求的除外。
- **不撞脸**：每个方向和拆过的标杆并排看；沿用基线不算撞脸。
- **眯眼看**：首屏做出来后眯起眼只看明暗块面，块面分布相似就回到骨架重做，不靠换装饰补救。

## 8. 问用户的方式

独立使用、方向未定时，把三个方向各用三四行写给用户：给人什么感觉、首屏长什么样、用什么字体和色彩、主视觉靠什么；附上推荐哪一个和理由，问一次：按其中一个直接做，还是三个都做成首屏比较。用户选定后补全方向卡再开工。自选时（用户说“你定”、上游 goal 模式、无人值守），同样写出三个方向，在设计说明里记下选了哪个和理由。

## 9. 记忆点

每个方向选一两处集中发力，其余保持安静。去这些地方找：

- **用户的动作**：点按、拖动、切换、提交，比滚动更容易被记住。
- **关键时刻**：完成任务、付款成功、上传、等结果；这些时刻情绪最强，一个小动作回报最高。
- **边角页面**：空状态、加载、404、页脚，没人期待，最容易出彩。

怎么想：让结果当场发生（被影响的东西当场变化，而不是只换一个图标）；把数字画成看得见的量（面积、长度、个数）；借这个领域里的真东西交付结果（音轨、图层、包裹、账单）；画法要说得出来源，选了就从主视觉一路用到图标和空状态。

精修时，记忆点和其他有辨识度的选择写进“保留”，别被磨平。
