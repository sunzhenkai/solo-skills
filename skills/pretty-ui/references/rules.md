# 规则（地板）

[pretty-ui](../SKILL.md) 的 refine、review 与 build 自查读本页。每条问题都要指得到一个规则号；指不出规则的意见算个人口味，要么找到规则，要么删掉。项目有成文设计规范时，规范先于本页；规则与项目的刻意约定冲突时，约定先行，在交付说明或问题清单里写明冲突。

## 1. 扫查顺序

```
H 层级 → S 间距与布局 → T 排版 → C 色彩 → D 深度 → I 图像与图标 → F 收尾与状态 → M 动效
```

顺序有因果：层级没理顺时，同一个问题会同时冒充间距、颜色和边框问题；间距没理顺时，会多报一堆“该加边框”；颜色先于深度，因为多数深度手法本质是颜色关系；结构坏了谈收尾没有意义。乱序扫查会产出一修就消失的问题，清单读起来像噪音。

评审 AI 生成的界面时，先过一遍 X 组：这些毛病最稳定，又最容易被生成它的模型自己漏看。

## 2. 严重度

| 级别 | 含义 | 对应 |
| --- | --- | --- |
| P0 | 影响可用：看不清、找不到、会出错 | Blocker |
| P1 | 影响一致：偏离体系、层级打架 | Major |
| P2 | 打磨：完成度与精致度 | Minor |

P0 清单（即使用户只问了别的，也要报）：

- 层级塌陷，看不出这一屏是干什么的（H1）。
- 文字对比度不达标：正文低于 4.5:1，大字低于 3:1（C4）。
- 含义只靠颜色传达（C5）。
- 图片上的文字有一部分看不清（I2）。
- 分组间距含糊，可能让人填错或点错（S3）。
- 正文行长严重越界：中文每行超过 46 字或少于约 15 字，英文超出 45–75 字符很多（T2）。
- 破坏性操作被做成页面主操作（H6）。
- 在支持的视口里布局破损、内容被裁或溢出（S8）。
- 依赖内容的视图没有空状态（F4）。
- 图解或关键插图渲染失败、离线缺失，只剩报错或空白（I6）。

## 3. 规则

### H 层级

- **H1** 每屏说得出唯一最重要的元素；强调靠压低竞争者，而不是继续给主角加码。
- **H2** 主次靠字号、字重、明度三个杠杆配合；文字颜色不超过三档，字重不超过两档，界面文字字重不低于 400。
- **H3** 标签是次要的：能直接表意的值就去掉“标签：值”的格式，或合并、降级标签；规格类内容里，用户扫视找的那一项才加重。
- **H4** 标题大小按它在页面里的级别定，而不是按标签名（h1、h2）定；语义标签保留，样式单独写。
- **H5** 图标比旁边的文字浅一两级；细线边框看不清时加粗而不是加深。
- **H6** 每页一个主操作，次要操作用描边或弱底，辅助操作用链接样式；破坏性操作按级别排，只有在确认对话框里它才是主操作。
- **H7** 内容页首屏是第一排内容或工作区，导航和标题区不把内容推出首屏。

### S 间距与布局

- **S1** 从宽松开始再收紧；密集的界面是刻意选择，写得出理由。
- **S2** 间距、尺寸取自刻度；相邻两级刻度至少差约 25%，避免靠近却不同的值。
- **S3** 组外距离大于组内：标题离下文比离上文近，标签离自己的控件比离上一组近，列表项之间小于列表与下一节之间。
- **S4** 内容决定宽度：表单、卡片、正文各有最大宽度，而不是拉满视口；宽内容可以分栏。
- **S5** 固定尺寸的元素（侧栏、图标、头像）用固定宽度；小视口里任何元素都不比大视口时更宽。
- **S6** 手机布局是单独设计的，大元素缩得比小元素快；组件内边距随字号变化。
- **S7** 对齐到少数几条锚线：整页的标题和正文块共享两三条左边缘起点。
- **S8** 1280 与 375 两个视口都没有横向溢出、重叠、裁切；点击区域至少约 40×40px。
- **S9** 一处分隔只用一种手段：间距、底色差、边框、阴影四选一，通常间距或底色差就够。

### T 排版

- **T1** 字号取自字阶，界面里同时使用的字号控制在五六种以内。
- **T2** 正文限宽：中文每行约 30–40 字（上限 46），英文 45–75 字符；段落宽度独立于外层内容区。
- **T3** 行高随字号和行宽变化：中文正文 1.6–1.75，英文正文 1.5–1.6，大标题 1.1–1.35。
- **T4** 正文字号：中文阅读页 16–18px，产品界面 14–16px，密集工具 13–14px；小于 12px 的文字只用于非阅读性的标注。
- **T5** 同一行里字号不同的元素按基线对齐。
- **T6** 超过两三行的文字左对齐；表格里的数字列右对齐，数字用等宽数字。
- **T7** 两端对齐只在开启断字的英文里用；中文正文默认左对齐即可。
- **T8** 全大写的英文要放宽字距；中文界面里少用英文大写标签。
- **T9** 大标题略收紧字距；中文标题不在末行留下单独一个字（`text-wrap: balance`）。
- **T10** 链接密集的区域用较弱的链接样式（颜色或下划线二选一），正文中的链接要看得出能点。

### C 色彩

- **C1** 颜色取自色阶：灰阶约 8–10 级，主色和每个语义色各有 5–10 级；用时引用 token，而不是在用到的地方临时调亮、调暗或混色。
- **C2** 色阶两端饱和度升高，黄、橙一类色相变深时转向橙红而不是发棕；灰阶带一致的冷暖。
- **C3** 强调色有预算：主操作、当前选中、关键数据用它，其余交给灰阶；一屏里大块的深色饱和色块不压过主操作。
- **C4** 每一组真实出现的文字 / 背景配对都量过：正文至少 4.5:1，大字至少 3:1，非文字元素至少 3:1。
- **C5** 含义同时由文字、图标或形状承载，颜色只是加强。
- **C6** 有色底上的次要文字用同色相的浅一级或深一级，而不是灰字或半透明白。
- **C7** 语义色只表达状态，组件里用语义 token（`--danger`），而不是色相名（红色）。
- **C8** 渐变两端的色相相差不超过约 30°，用于背景时对比要低，远离文字。
- **C9** 暗色模式重新映射语义层：表面从深灰起步，有色元素降饱和后重新量对比度。

### D 深度

- **D1** 光源来自上方：阴影只向下偏移、不横向偏移；凸起元素上沿浅、下方有阴影，输入框这类凹陷元素上方有内阴影。
- **D2** 阴影取自五级阴影，按离用户多近选：按钮小、下拉中、模态框大；同类组件阴影一致。
- **D3** 按钮有按下状态，可拖动的元素拿起时升高；两段阴影各司其职，层级越高接触阴影越淡。
- **D4** 扁平或暗色界面靠颜色关系表达深度；一个整体扁平的设计里，不突然出现一个柔光大阴影。

### I 图像与图标

- **I1** 图片质量配得上它占的面积；屏幕截图缩到看不清时，改为局部特写。
- **I2** 图片上的文字在整张图上都读得清：用遮罩、降低图片对比或给文字垫底，只用到刚好够的程度。
- **I3** 小图标按设计尺寸用，放大三四倍会显得粗糙；需要大图标时换大尺寸的图标或加底框。
- **I4** 用户上传的图片放在固定比例的容器里裁切；白底图片和白色表面之间有分界。
- **I5** 一个界面只用一套图标，描边粗细和端点一致；装饰性图标标 `aria-hidden`，只有图标的按钮有可读名称。
- **I6** 图解和关键插图随页面一起交付：用内联 SVG 或 HTML/CSS 画出，配一句文字结论；运行时从网络加载渲染库的图，离线或语法出错时整块只剩报错。

### F 收尾与状态

- **F1** 列表符号、引号、链接和表单控件不停在浏览器默认样子。
- **F2** 长页面有底色变化或分区节奏，而不是从头到尾一种背景。
- **F3** 组件库的默认样子被调整进了方向：按钮、输入、选中、标签共用一套控件语法。
- **F4** 每个依赖内容的视图都有设计过的空状态，空状态里只显示有用的入口，用不了的功能先隐藏。
- **F5** 加载、出错、禁用、处理中各有自己的样子；状态变化时点击区域不变大变小，也不挤动旁边的布局。
- **F6** 文案像真的：按钮写清动作（“保存草稿”而不是“提交”），错误信息说明原因和下一步，数字带单位和格式。
- **F7** 键盘可达：每个可交互元素有清楚的 `:focus-visible` 样式，只在悬停时出现的入口也有键盘和触屏的到达方式。
- **F8** 减法做过：填缝的小字、写在界面上的设计说明、“示例”“仅供示意”之类的字样删掉；删完主角更突出，而不是画面只是变空。

### M 动效

- **M1** 动效服务理解：反馈操作结果、交代元素从哪来到哪去、引导注意；一页里集中在一两处记忆点。
- **M2** 只动 `transform` 和 `opacity`；常规交互 150–250ms，较大的转场 300–400ms；进入用减速、离开用加速。
- **M3** 主操作有即时反馈，状态切换看得出来路；首屏内容不会停在透明的出场前状态。
- **M4** 尊重 `prefers-reduced-motion`：关闭位移和缩放，只保留必要的淡入淡出。

### X AI 默认样貌

逐条看它是否在画面上。品牌、用户要求或写得出产品依据的做法不算；其余改掉，或在交付说明里写明它怎样服务方向。

- **X1** 没有品牌依据的靛蓝、紫色主色，或直接套用品类最顺手的配色。
- **X2** 蓝到紫、紫到粉的大跨度渐变，渐变文字，无来由的发光与光晕。
- **X3** 所有内容居中对齐。
- **X4** 一个间距值用到底，分组看不出来。
- **X5** 表情符号当图标。
- **X6** 每张卡片都带大阴影；边框、阴影、底色差叠在同一个元素上。
- **X7** 每个动作都是实心按钮。
- **X8** 处处圆角卡片、卡片里再套卡片、每个层级都画线框，画面被切碎。
- **X9** 标题上方的眉标或编号标签，而内容并没有真实的顺序；给普通卡片加一条彩色单侧粗边线当装饰。
- **X10** 没来由的“左边大标题 + 右边说明或图片”首屏；后台退回“四张等宽指标卡 + 满屏彩色胶囊”的模板。
- **X11** 空泛的比喻式文案、填缝短句，以及只有理想数据、没有空和错的界面。
- **X12** 中文界面里的英文大写标签、用系统字体拉开字距冒充品牌字标。

## 4. 误报

下面这些看起来像违规，其实不是；报出来会损害评审的可信度：

- 刻意的高密度后台或数据工具（S1）。
- `max-width: 36em`、`70ch` 这类按字数写的宽度值，它正是在表达行长规则（T2）。
- 衬线字体：这是性格选择，不是错误。
- 完全没有阴影：扁平设计成立，检查深度是否由颜色承担（D4）。
- 居中的短标题或一两行的标语（T6）。
- 视觉上隐藏的标题（H4）。
- 同一列内容里宽度不同的段落与表格（T2）。
- 确认对话框里醒目的红色删除按钮：这里破坏性操作就是主操作（H6）。
- 上下不对称的标题外边距（S3）。
- 两块不同的底色之间没有边框（S9）。
- 侧栏当前项的指示条、正文引用的竖线（X9）。

## 5. 矫枉过正

规则用过头同样是问题：

- 所有内容挤进一条窄居中栏：表格和图解需要更宽的空间（S4）。
- 次要文字淡到读不清：规格类内容里标签和值只差一级（H3）。
- 细线加深成满屏深色网格：要加粗并保持柔和的颜色（H5）。
- 删光所有边框导致什么都分不开：是少用，而不是不用（S9）。
- 数据工具上留出巨大的空白：刻意的密度是合理的（S1）。
- 色阶越调越多：微调已有色阶可以，新增色阶会破坏体系（C1）。
- 拟物的斜面和渐变：模拟光源点到为止（D1）。
