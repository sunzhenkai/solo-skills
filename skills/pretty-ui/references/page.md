# 阅读页（page 模式）

[pretty-ui](../SKILL.md) 的 page 模式读本页：把用户给的上下文、文件、报告、方案或评审内容做成可离线打开的静态 HTML 阅读页。保留原内容的事实、术语和层次；可以重组信息以改善阅读，只呈现输入里真实存在的内容。输入的 Markdown 只是内容来源，直接产出 `.html`，不另建 Markdown 副本。

## 1. 输出根

- 默认输出到 `docs/pretty-ui/`，下文记作 `<output-root>`。
- 仓库里已有 `docs/pretty-view-html/index.html`（本 skill 改名前的输出）且用户没指定路径时，继续用 `docs/pretty-view-html/` 作为 `<output-root>`，在交付说明里写一句。
- 用户指定其他路径时，以用户要求为准。

## 2. 流程

1. **读全部输入**：确认主题、读者、内容边界和主要阅读任务（通读、查找、对比、照着操作）。
2. **查现状**：定下 `<output-root>`，看根聚合页和已有输出的标题、摘要与路径，判断有没有可以共同维护的同主题内容。
3. **同主题不重组**：发现同主题时，本次内容照常写成独立页面并登记入口，已有文件不移动、不覆盖；按第 5 节写出归类方案，放进交付说明。
4. **单页还是多页**：默认单页；只有内容由多个可独立阅读、分享或维护的主题组成，或用户明确要求时才拆多页。篇幅长本身不是拆页理由。
5. **轻量方向卡**：按 [SKILL.md](../SKILL.md)「轻量方向卡」写，填进模板顶部的注释里。同一内容包共用一张卡；根聚合页已存在时沿用它的视觉语言。
6. **生成**：从 [assets/reading-page.html](../assets/reading-page.html) 起手，复制后改标题、导航链接、方向卡注释和 `:root` 色值，正文换成真实内容；布局按第 6 节，组件按第 7 节；需要架构、流程、关系、状态、时序等图解时，读 [html-diagram/REFERENCE.md](html-diagram/REFERENCE.md)，按它选型并嵌入当前阅读页，默认不另建独立图解文件。
7. **检查与看图**：对 `<output-root>` 跑 `python3 scripts/check_page.py --offline <output-root>`，报错项修完；按 [evidence.md](evidence.md) 截图并量行长（阅读页默认响应式），修掉溢出、过长的行、孤字和被裁的表格；看不了图时在交付说明里写“未渲染验证”。
8. **更新入口**：更新内容包首页与根聚合页（第 4 节），逐条过第 8 节的完成检查。

## 3. 文件组织

名称用简短、可辨识的 kebab-case slug。

单页：

```text
<output-root>/
├── index.html
└── <slug>.html
```

单页文档本身是完整的阅读入口，并提供返回根 `index.html` 的链接。

多页：

```text
<output-root>/
├── index.html
└── <slug>/
    ├── index.html
    ├── <topic-a>.html
    ├── <topic-b>.html
    └── assets/            # 可选，共享样式、脚本或图片
```

- 包内 `index.html` 是这个内容集的聚合页：说明主题、范围，并列出全部页面。
- 内容页用一致的导航，至少能返回包首页；适合顺序阅读时再提供上一篇 / 下一篇。
- 页面较多且有真实、稳定的父子分类时才加分组目录，每个分组目录有自己的 `index.html`；默认不超过两级内容层次。
- 多页共享的样式和脚本只在包内 `assets/` 放一份。

### 本地链接

每个本地 `href` 和 `src` 都以**包含这个链接的 HTML 文件所在目录**为基准计算相对路径。输出目录可能在任意位置、任意层级，按实际目录逐级计算。

- 本地链接只用 `./`、`../` 或不带前导斜杠的同级路径；站点根 `/…`、绝对磁盘路径和 `file://` 在换目录后都会失效。
- 链接里只写相对当前文件的路径。例如页面位于 `<output-root>/index.html` 时，内容入口写 `./<slug>.html` 或 `./<slug>/index.html`，而不是 `<output-root>/<slug>.html`。
- 包首页链接同目录页面用 `./<topic>.html`；包内页面返回包首页通常用 `./index.html`，返回上级聚合页通常用 `../index.html`。更深的层级按实际目录逐级计算，不机械照抄示例。
- 样式、脚本、图片、迁移页目标和导航链接遵守同一基准；HTTP(S) 外部链接不受此限。

先确定最终文件布局，再为每个 HTML 文件分别计算链接。写入后用 `check_page.py` 从每个文件的父目录解析全部本地链接，确认目标存在、没有越出输出范围。

## 4. 根聚合页

`<output-root>/index.html` 是全部生成内容的总入口，持续维护：

- 每个单页或多页内容集只登记一个入口；多页指向包内 `index.html`。
- 展示清楚的标题、一句说明和必要的日期或类型，不暴露实现细节。
- 新增、移动、改名或删除内容时同步更新，保持没有死链和重复条目。
- 已存在时保留原有内容与视觉语言，在其基础上增量更新；不存在时建一个简洁的响应式索引页，按索引页自己的阅读任务设计，不必套用某篇内容页的配色。

写入前检查目标路径：同名内容已存在、用户又没明确要求覆盖时，换一个不冲突的 slug 并在结果里说明；用户明确要求才覆盖。

## 5. 同主题内容包

“同主题”指内容围绕同一个核心对象、问题域或连续的阅读任务，合并后有明确的共同维护价值；关键词重合、文档类型相同或领域大致相同都不够。

发现同主题后，在交付说明里写出归类方案：

- 归类依据，拟纳入和明确不纳入的页面；
- 内容包标题、slug、页面结构和目标路径；
- 现有链接、根聚合页入口和旧路径怎么处理。

本次写入不动已有文件；用户明确确认后另起一次改动，才把相关内容重组为同一个多页内容包。重组时保留旧路径可达，可以用指向新入口的轻量迁移页承接旧链接；根聚合页只登记新的内容包入口。用户没确认、要求调整或主题关系不可靠时，现有文件保持不动。

## 6. 阅读布局

- **导航**：每页一致的顶部导航，至少有根聚合页入口，内容包内再给包首页和当前位置。导航用 `position: sticky; top: 0`，背景足以遮住滚动内容；窄屏可换行或横向滚动，关键入口始终可见。
- **两种宽度**：页面容器可以宽（约 1200–1440px，配合 `clamp()` 侧边距），承载表格、代码、图解和对照；连续正文单独限宽，中文每行 30–40 字（上限 46）。正文宽度用 `px` 或 `rem` 写在列容器上（如 18px × 38 字 ≈ 684px）；写成 `em` 时每个元素按自己的字号算，小字说明会比正文窄一截。正文列和宽内容共享同一条左边缘。
- **字号与节奏**：正文 16–18px，行高 1.6–1.75；标题按字阶逐级拉开，标题离下文比离上文近；段落之间约一行的距离。
- **换行**：标题用 `text-wrap: balance`，正文段落和列表项用 `text-wrap: pretty`，避免末行孤字；一行里的多项元信息用间距或标签分开，窄屏换行时不留下悬在行首行尾的 `/`、`·`。
- **字体**：用模板里的系统字体栈，一套无衬线加一套等宽通常就够；需要特征字体时随包附带字体文件，并保留中文回退。代码和等宽文字关掉连字（`font-variant-ligatures: none`），让 `<=`、`!=` 按原样显示。
- **宽内容**：宽表格和代码块在自己的容器里横向滚动，页面本身不出现横向滚动条。
- **语义与可达**：语义化 HTML，标题层级连续；有页面标题、`lang` 属性和 viewport；链接和控件文字清楚、有可见的键盘焦点和足够的对比度。
- **动效**：服务阅读，默认克制，尊重 `prefers-reduced-motion`；纯阅读页不为“高级感”加动画。
- **离线**：页面可以直接在浏览器打开；不依赖构建步骤、前端框架或联网加载的资源，图解用内联 SVG 或 HTML/CSS 画出来，而不是运行时从网络加载渲染库。

## 7. 组件与用色

按内容的职责选组件，组件服务扫描、对比和操作。普通叙述就用段落；只有内容本身是结构化的（对比、步骤、字段、状态）才用表格、步骤、定义列表这类组件。组件数量由内容决定，而不是预设一个“足够丰富”的数目。

| 职责 | 优先组件 |
| --- | --- |
| 内容表达 | 结论 / 摘要条、导语、定义列表、关键引用 |
| 标签 | 状态徽章、类型标签、版本或受众标记 |
| 架构 / 可视化 | 分层架构、流程步骤、关系图、状态与时序图、时间线（按 html-diagram 选型） |
| 对比 / 决策 | 对照表、方案并列、决策记录、取舍说明 |
| 教程 / 操作 | 有序步骤、检查清单、命令与代码块、`kbd`、注意事项 |
| 数据 / 状态 | 指标、进度、字段表、结果汇总 |

用色：

- 先在灰度下用字号、字重、明度和留白把层级立起来，再上色。
- 强调色只留给少数几处：当前位置、关键结论、主要链接。
- 语义色只表达真实的状态（成功、警告、危险、信息），并且同时有文字标签；没有状态含义的标签用中性底色。
- 类别之间优先用位置、形状、文字区分，而不是一类一色；同一页里彩色徽章和标签一多，强调就失效了。
- 同一内容包共用一套颜色含义；色值写成页面顶部 `:root` 里的 CSS 变量，组件里只引用变量。

只呈现输入里真实存在的信息，不为好看虚构指标、状态或对比项；卡片、徽章和提示框只用来编码真实的职责或语义。

## 8. 完成检查

- 输入里的核心事实、代码、表格、术语和结论没有遗漏或篡改。
- `check_page.py --offline` 没有报错；提示项已改掉或在交付说明里写了理由。
- 按 evidence.md 的目标视口看过截图（或写明“未渲染验证”）：没有溢出、遮挡、过小文字；正文每行不超过 46 字。
- 单页能返回根聚合页；多页有包首页、完整页面地图和一致导航。
- 根 `index.html` 有本次内容的唯一入口。
- 发现同主题内容时，已有文件没有被移动或覆盖，归类方案写在交付说明里。
- 含图解时已按 html-diagram 选型并嵌入阅读页，离线可见。
