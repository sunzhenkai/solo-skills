# 弯路复盘

会话里有一次付出明显代价的排查时，把过程提炼成按现象可检索的坑候选，交给知识落点。目的是让下次遇到同样现象时少走同一段路，而不是写事后报告。

## 何时做

命中任一信号就做，都不命中则跳过：

- 排查记录里有 `dead-end` 路径或被推翻的假设；
- 用户纠正过排查方向；
- 最终根因与最初的猜测不同；
- 轮次或耗时明显超出问题本身的难度。

## 取材

优先读 `trouble-grill` 已落盘的排查记录：taskrail 任务目录的 `evidence/diagnose.md` 与 `context/current.md` 结论表，或工作区约定的存档位置。没有记录时从对话提取，只用对话里有证据的内容。根因未坐实时照常复盘，候选标为未定位。

## 五问

1. **现象**：最初看到了什么？报错原文、现象描述、误导性的表面结论。
2. **误判**：先后怀疑过什么，各自被哪条证据推翻，绕了几轮？
3. **决定性证据**：哪一步一锤定音？按当时已有的信息，它最早能在哪一步做？
4. **最短路径**：知道答案后重来，前 1–3 步做什么？
5. **可迁移规律**：去掉主机、项目、版本等专名后，哪条规律还能用在别的系统上？

答不出的写「未知」，保持空缺而不补猜测。

## 分流

| 内容 | 落点 |
| --- | --- |
| 具体问题的现象、误判、根因与最短判别 | 坑候选，由 `wiki-data` 写成 `kind: pitfall` 的经验页；没有 wiki 时用既有知识库，都没有就留在交接 |
| 去掉专名后仍成立的规律 | 在坑候选里标为模式候选，由 `wiki-data` 判断是否归纳成排查模式 |
| 排查方法本身的弯路：检索词偏差、跳过能一刀切分的对照实验、在错误的层反复试 | 写进坑候选的误判；已有坑页记过同类弯路时，建议用 `skill-upgrader` 改进排查 skill |
| 只对本任务成立的细节 | 当前任务 SUMMARY 或交接 |

## 坑候选

写进收尾清单的知识落点，每个坑一条：

```text
- 坑：<现象 → 根因，或「现象 → 未定位」>
  现象词：<报错原文、现象描述，逗号分隔>
  误判：<怀疑过什么 → 被什么推翻>；绕了 <N> 轮
  最短判别：<决定性实验>；重来时先做 <1–3 步>
  根因：confirmed <因果链> / 未定位（已排除 <假设>）
  模式候选：<去掉专名后的规律，或「无」>
  证据：<排查记录路径或对话依据>
```

写 wiki 列为收尾清单的直接执行项，随本轮确认执行；写入前由 `wiki-data` 按现象词检索同类坑，同一个坑复发时追加到原页。
