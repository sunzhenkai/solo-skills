# 未完成判定、暂停挂起与彻底中止细则

当主线尚未达到完成标准时，收尾的首要动作是确认「继续做完、暂停挂起，还是彻底放弃」，而不是按已完成路径推进提 MR/PR、合入主分支、打 tag 或删分支。

## 1. 何时进入未完成门禁

命中以下任一情况即判为未完成，立即进入本细则：

- 用户明确要求中的任意一项尚无对应产物、答案或结论；
- 原始场景尚未运行验证，或核心验收失败且尚未修通；
- 存在阻塞后续交付的未解决问题（外部依赖未就绪、权限/环境缺失、关键决策未定）；
- 用户在任务中途主动要求停下来、暂停或结束会话。

进入未完成门禁时，跳过完成态的代码合入主分支、打 tag、发版与部署检查。

## 2. 第一轮三选一门禁

第一轮先用 2–3 行大白话写清两件事：**已经做到哪**、**还差什么或卡在哪**，随后把方向选择作为首位拍板题（2–3 个选项，推荐项放首位并附一句理由）：

1. **继续做完（退出收尾）**：缺口较小或可当场补齐时优先推荐。选择后退出收尾流程，不执行清理或归档，直接回到主线补齐缺失项，完成后再收尾。
2. **暂停挂起（保现场、留断点）**：后续还要继续推进（如等外部依赖、改天再做）。重点是安全固化现场并写清恢复入口。
3. **彻底放弃（安全撤场）**：确认不再推进（方案被推翻、需求取消）。重点是逐项确认清理半成品、关闭任务、消除遗留影响。

## 3. 暂停挂起清单（保现场 + 留断点）

用户选择「暂停挂起」时，按以下原则准备动作并逐项确认：

- **保住代码现场**：保留当前分支与 worktree，不推进合入默认分支、打 tag 或发版。未提交改动由用户选择保全方式（保留在工作区 / 做本地 WIP 提交 / 推送到个人备份分支），各动作授权互不外延。
- **清理运行态与共享影响**：确认后停掉本会话启动的本地服务、后台任务和容器/端口占用；若修改过会影响他人或后续日常开发的共享临时开关/配置，确认后还原。
- **固化恢复入口**：
  - 使用 `taskrail` 时：保持任务为 `active`（不调用 `close` 归档），将已完成进度、当前阻塞点和下一步操作写回台账（如 `context/current.md`）。
  - 无 `taskrail` 时：询问是否把断点记入项目已有工作记录；不新建额外报告文件，第二轮直接写清所在仓库、分支、worktree 路径及下次接续第一步。

## 4. 彻底放弃清单（安全撤场）

用户选择「彻底放弃」时，逐项确认撤场动作，避免留下半成品或误删有用资产：

- **半成品代码与 PR/MR**：逐项确认是否丢弃未提交改动、关闭草稿 MR/PR、删除临时分支与临时 worktree；清理前先核对无无关未提交改动或独有重要提交，未知文件保留。
- **运行态与临时痕迹**：停掉临时服务、容器/端口与后台任务，还原调试日志、mock、跳过校验开关或临时配置。
- **任务归档**：使用 `taskrail` 时，路由到 `taskrail` `close` 按未完成关闭（状态为 `archived`，而非 `done`），写明放弃原因与已验证/未验证边界，不伪写成功总结。
- **按信号附带经验**：若放弃前曾绕过明显弯路或踩出通用坑，可附带询问是否将坑候选写入 `wiki-data` 或既有知识库；未命中信号则跳过。

## 5. 第二轮汇报口径

- **已暂停挂起**：开头明确「已按确认暂停，现场和断点已保好」，列出分支/worktree/改动留在哪、停掉了哪些临时服务、下次从哪一步直接接手。
- **已确认中止**：开头明确「已确认中止并完成撤场，没有遗留影响」，列出丢弃或关闭了哪些半成品、任务已按未完成归档（或确认不留）、顺手保留的有效经验（如有）。
