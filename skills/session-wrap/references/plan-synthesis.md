# 收尾清单与两轮输出细则

收尾分两轮：第一轮列收尾清单，只对需要拍板的项提问；用户确认后统一执行，第二轮汇报收尾结果并重列缺口。本文件给出归属判据、提问规则、排序、缺口落点、确认语义与反例。

## 归属判据

| 归属 | 判据 | 典型事项 |
| --- | --- | --- |
| 直接执行 | 本机、可逆、结论唯一，不做会留下错误现场 | 缺口记账、证据落盘、恢复入口、停掉本会话启动的临时服务、临时产物归位、落点唯一的坑候选写入 wiki |
| 需你选择 | 有两种以上合理做法，或用户可能有不同取舍 | 提交范围与说明、合入方式、任务是否收口、是否补验或如何补验 |
| 需你选择（逐项授权） | 外部、不可逆、跨机或影响共享系统 | push、合入共享分支、部署、删除、清理 worktree、跨机同步、写外部 tracker |
| 缺口 | 超出本次目标，或需要审美、产品、范围判断 | 旧 bug、技术债、过时文档、环境隐患、用户提到的后续优化 |

提交属于用户点名才做的动作，始终作为需你选择的一题；范围清楚时把它作为推荐项给出。

## 提问规则

- 每项一题，2–3 个选项；推荐项放首位，标「推荐」并附一句依据。
- 题干脱离上下文也能看懂：写清对象、范围和影响，例如「`<repo>` 有 N 项未提交改动，混有其他任务的文件」。
- 同类事项合成一题，例如同一仓库的提交范围；外部或不可逆动作一项一题，题干写明目标环境（远端、分支、机器）。
- 能由规则、证据或用户已确认的偏好定下来的，归入直接执行，不提问。
- 宿主有结构化提问工具时用它发问，正文只留清单摘要；没有时在正文用编号与选项列出。

## 排序

1. 补验或修复当前目标的缺口；仍未通过（含按选择跳过补验）时第二轮结论为仍有阻塞，并写明是哪一项。
2. 提交、任务状态与收口流程。
3. 台账记账与知识落点。
4. 衍生任务与外部动作。

同一发现只出现一次；题目引用清单条目，不重复描述。

## 缺口落点

缺口记账是直接执行项，按执行时的任务状态取落点（本轮先收口的任务按已收口处理），取第一个可用的：

1. 任务未收口：写入 `context/current.md` 的「未决问题」表，`解决形式` 写「另开任务」或「不纳入」。
2. 任务已收口或已归档：在 SUMMARY「剩余风险与后续项」追加一行，注明来源会话与证据；只追加，不改写 SUMMARY 其余部分。
3. 有 Issue 等 tracker：写入属于外部动作，作为需你选择的一题；未获授权时退到下一条。
4. 都没有：只留在第二轮的缺口列表，不新建文件。

记账不新建任务或子任务；用户点名「另开任务」时再路由到 taskrail 或已有 tracker。

## 确认语义

- 第一轮不执行收尾动作，只读取证照常进行；没有需你选择的项时直接执行并进入第二轮。
- 用户一次回答覆盖本轮清单：直接执行项与各题所选项按排序执行，可中途叫停。
- 每题的选择只授权该项，不外延到其他动作：选了提交不等于授权 push，选了合入不等于授权部署。
- 缺口不因确认而处理；未点名时只记账。
- 执行中新发现要加项或升级风险，再问一轮。

## 两轮输出

- 第一轮：收尾清单，分将直接执行、需你选择、缺口（写明将记入的落点）三块；不下结论。
- 第二轮：结论、收尾结果（每项写已完成、按选择跳过或失败及原因）、缺口列表（事实 → 记在哪 → 建议处置）、恢复入口。
- 空章节省略；每条一行；必要时补一行依据路径。

## 反例

- 先报「可结束」，再把未定的提交、清理列在后面等用户自己处理。
- 单列一段「已核对事实」复述验证流水。
- 把拿不准的事列成被动的「需授权」清单就结束，不给选项和推荐。
- 缺口只写「只记账」，没有实际记账，也没写落点。
- 对能由规则定下来的事提问，或把发现清单原样丢回给用户。
- 把多个外部动作合成一题，或用一题的选择顶替其他动作的授权。
- 为凑格式生成复盘或额外报告文件。
