# 方案合成与输出细则

收尾阶段把取证结果合成一个方案，而不是把发现清单和问题交给用户。本文件给出分档判据、排序、缺口记账与输出要求。

## 三档判定

| 档位 | 判据 | 典型动作 |
| --- | --- | --- |
| 收尾项 | 本机、可逆、结论唯一，不补齐会留下错误现场 | 证据落盘、台账记账、恢复入口、停掉本会话启动的临时服务、临时产物归位 |
| 方案步骤 | 本机，但改变交付状态或需要用户拍板 | 提交、建任务、写文档 / wiki、任务置 done、跑收口流程 |
| 单独授权 | 外部、不可逆、跨机或影响共享系统 | push、合入共享分支、部署、删除、清理 worktree、写外部 tracker |

不属于三档的发现就是额外缺口：给出事实、证据、影响和建议处置（处理 / 另开任务 / 不纳入），等用户点名。

提交不因为「会话结束」进入收尾项：提交范围与 message 需要判断，仍走方案确认。

## 排序

1. 补验或修复当前目标的缺口；仍未通过时结论为仍有阻塞。
2. 提交、任务状态与收口流程。
3. 台账记账与知识落点。
4. 衍生任务与外部动作。

同一证据或同一文件只写一次；方案步骤引用缺口编号，不重复描述。

## 缺口记账

用户只授权收尾项时，额外缺口写进台账，不遗忘也不擅自扩大范围：

- taskrail 任务：写入 `context/current.md` 的「未决问题」表，`解决形式` 写「另开任务」或「不纳入」；不代写 `SUMMARY.md`，不新建子任务。
- 有 Issue 等 tracker：写入属于外部动作，等授权。
- 没有台账：留在会话交接，不新建文件。

## 输出要求

- 四块：结论、收尾方案、额外缺口、需单独授权；加恢复入口。
- 空章节省略；每条一行；必要时补一行依据路径。
- 方案是一个有序序列，步骤可执行、可叫停；不写「选项 A / B」式选择题。
- 可选项最多三项。

## 确认语义

- 一次确认等于授权方案内全部编号步骤，不含「需单独授权」项。
- 「需单独授权」按目标环境逐项点名，不随方案确认生效。
- 额外缺口不因方案确认而处理；未点名时只记账。
- 中途扩充方案或提升风险，重新确认。

## 反例

- 把多条发现和「待你确认」问题原样丢回用户。
- 把外部动作混进方案执行组。
- 对同一条发现重复描述或重复列清单。
- 为凑格式生成复盘或额外报告文件。
