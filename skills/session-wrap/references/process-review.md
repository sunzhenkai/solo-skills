# 过程复盘

用户要求复盘、分析过程或优化流程时，检查本次会话的执行过程，找出值得保留的做法和有证据的改进点。普通收尾不展开本环节。

## 取证

只使用对话、已有任务记录、排查记录和实际验证记录，不为复盘额外扫描仓库。按意图确认、探索、实施、验证和返工重建粗略过程，只分析影响明显的阶段。

有时间戳时据此计算耗时，区分执行、工具运行、外部等待和用户等待；没有时间戳时只比较阶段、返工和等待，明确无法准确计时，不编造分钟数或占比。事实不足的项标为未知。

## 提取发现

从同一过程提取以下发现，空项省略，不拆成额外流程：

- **主要耗时**：时间或轮次主要花在哪，原因是探索、返工、验证还是等待。
- **坑与返工**：哪些假设、方案或产物被推翻，代价是什么，哪条决定性证据本可更早取得，下次最短路径是什么。
- **可精简**：哪些目标偏移、设计、检查或沟通没有带来相应价值。过度设计须有超出目标、无现实风险收益或无实际复用对象等依据；过度检查须有重复证据、执行后没有新信息或成本明显高于风险等依据。
- **应保留**：哪些提问、决策或验证降低了风险与返工，复用条件是什么。

分析原因时同时检查目标偏移、关键假设、决策依据、沟通节奏和验证盲区，不另设固定章节。必要的安全、授权和原始场景验证不能仅因耗时判为过度检查。

排查弯路的坑候选仍按既有弯路复盘规则沉淀；过程复盘只引用对应发现，不重复生成候选。

## 优化方案

每条建议必须对应一个具体发现，写清改什么、预期减少的成本，以及可能损失的保障或适用边界。优先调整下次执行顺序、提问或验证方式；需要修改文档或其他 skill 时只给出建议，按对应流程另行确认，不因单次会话自动修改。

## 输出

在第一轮收尾清单前直接输出，不新建报告文件：

```text
过程复盘
- 主要耗时：<阶段> → <原因与证据>
- 坑与返工：<问题> → <代价> → <下次最短路径>
- 可精简：<设计 / 检查 / 沟通> → <判定依据>
- 应保留：<有效做法> → <作用>

优化方案
- <具体调整> → 对应 <发现> → <预期收益>；边界：<可能风险>
```

需要执行的优化仍按风险与授权归入现有收尾清单，不在优化方案和清单中重复描述。
