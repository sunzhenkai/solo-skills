# Session Wrap

把会话收成两件事：本次的事做完收好，超出本次的缺口记进台账。分两轮：第一轮列收尾清单，只对需要拍板的项给出带推荐的选项；用户确认后统一执行，第二轮汇报收尾结果并重列缺口。

`anti-lazy` 负责交付前的意图与差距检查；taskrail 任务的 `close` 负责 SUMMARY、状态和归档。本 skill 面向整个会话补查遗留事项，不复制它们的产物。

## 收尾流程

### 1. 对照目标

重读最初目标和最新要求，让每项明确要求对应到产物、回答或证据。区分「已完成且已验证」「已完成但未验证」「未解决或已放弃」，以及被新证据推翻的假设。

完成标志：原始场景和每项「必须」都有结论；核心缺口仍标为待补或阻塞，没有转成后续事项来规避本次交付。

### 2. 按现场取证

只检查与本次工作有关的真实现场，区分事实、推测和未知：

- 有代码改动：核对 diff、git 状态、分支 / worktree、未跟踪文件和实际验证记录。
- 有任务台账：核对 TASK、SUMMARY、子任务与索引的当前状态。
- 有外部操作：核对 PR / MR、CI、release、部署、消息等实际结果。
- 有后台活动：核对任务、服务、容器、定时动作或委派工作的状态。
- 纯问答或方案讨论：依据对话收尾，不为形式扫描仓库。

验证不足时建议补验；静态检查、编译或工作量不能替代用户原始场景的验证。

### 3. 选择收尾事项

命中才检查，未命中不展开：

- **交付**：遗漏要求、未验证项、失败检查、剩余风险和必要的回滚说明。
- **一致性**：行为、配置、命令或架构变化后，README、AGENTS、接口与迁移文档是否仍准确。
- **Git**：未提交改动、疑似密钥、未推送提交、未合并分支、进行中的 merge / rebase。
- **发布**：changelog、版本、tag、PR / MR、CI、部署、监控、回滚与外部通知。
- **环境**：临时配置、调试开关、测试数据、代理、端口转发、临时权限、feature flag、服务与后台任务。
- **清理**：本次产生的临时产物和 worktree；先核对未提交改动、独有提交及使用中的资源，未知文件保留。
- **交接**：剩余问题、待用户决策、下一动作、证据位置和恢复入口。

### 4. 推荐分支合入

发现未合并任务分支时，核对 source / target、默认分支、已有 MR / PR、CI / 评审、分支保护、仓库历史合入方式和提交结构。用户习惯只采用本次明确选择或已确认的长期偏好，不从单次历史猜测。

按「仓库硬规则与分支保护 > 用户本次明确选择 > 已确认的长期习惯 > 仓库历史惯例 > 提交结构」裁决，给出一个主推荐，不只罗列选项：

- 已有 MR / PR：优先沿用，不重复创建；目标分支要求评审或 CI 时也走 MR / PR。
- 多个 WIP 提交属于一个逻辑改动，且用户或仓库偏好简洁历史：推荐 squash。
- 多个提交各自有意义且需要保留边界：推荐 merge commit；仓库要求线性历史时推荐 rebase merge。
- 直接合入：仅在仓库允许且符合用户习惯或仓库惯例时推荐；共享主分支仍需单独确认，push 不随合并自动授权。

推荐包含合入通道与历史处理方式，例如 `MR + squash`。证据不足时沿用仓库既有惯例并标明不确定；target 或强制规则无法判断时先查证，不猜默认分支。

### 5. 分流衍生问题

影响当前目标或 criterion 的问题留在当前交付中处理。与本次目标无关的旧 bug、技术债、文档缺漏或环境隐患，先查 workspace 与仓库已有的任务记录机制：

- 使用 taskrail：建议新建独立任务；只有存在真实交付依赖时才建议父子关系。
- 已有 Issue 等 tracker：建议使用同一机制；先检索相关记录，已有则补充证据与关联来源。
- 没有发现任务机制：把问题留在交接信息中，不为此新建一套机制。

建议任务包含问题、来源、证据、影响、复现方式（如有）、建议判据和相关路径。证据不足标为待查证，不把猜测批量转成任务。

### 6. 路由值得沉淀的内容

只沉淀跨任务仍有价值、现有文档尚未表达的内容；先找既有落点并去重，没有新经验就不硬造复盘。

| 内容 | 优先落点 |
| --- | --- |
| 当前行为、命令、持续约束 | 项目 README、AGENTS 或既有现行文档 |
| 架构与业务流程的代码映射 | `project-atlas` |
| 关键取舍与术语 | 项目已有 ADR / glossary 机制 |
| 可复用经验、踩坑、操作台账 | 既有知识库或 `wiki-data`，保留来源、置信度与时效 |
| 反复出现且通用的 skill 改进 | `skill-upgrader`；单次失败先留作经验 |
| 任务特例与本次认知更正 | 当前任务 SUMMARY；无任务机制时留在交接中 |

操作台账记录有追溯价值的动作、环境、结果、影响和回滚方式，不复制普通命令流水。

排查绕过路（有死路、方向被纠正、根因出乎最初猜测或明显超时）时，按 [references/detour-review.md](references/detour-review.md) 做弯路复盘，产出坑候选。

### 7. 列收尾清单

把前面每一步的发现合成一张收尾清单，每个发现只有一个归属：

- **直接执行**：本机、可逆、结论唯一，如缺口记账、证据落盘、恢复入口、停掉本会话启动的本机临时服务、临时产物归位。只列出，不提问。
- **需你选择**：有两种以上合理做法，或属于外部、不可逆动作。每项一题，2–3 个选项，推荐项放首位并附一句理由；同类事项合成一题。
- **缺口**：超出本次目标，或需要审美、产品、范围判断。记账本身是直接执行项；只有用户点名才处理，不新建任务、不改文档。

按依赖排序：补验当前缺口 → 提交 → 台账与知识落点 → 衍生处理。判据、提问规则、缺口落点与反例见 [references/plan-synthesis.md](references/plan-synthesis.md)。

## 确认与授权

- 第一轮只列清单与提问，不执行收尾动作；没有需你选择的项时直接执行并进入第二轮。
- 用户一次回答覆盖本轮清单：直接执行项与各题所选项按序执行，可中途叫停。
- 每题的选择只授权该项。push、合入共享分支、部署、删除、清理 worktree、跨机同步、写外部 tracker 各自成题，题干写明目标环境，遵循接收 skill 的门禁。
- 执行中新发现要加项或升级风险，再问一轮，不顺势扩展。

## 输出

空章节省略，每条一行；证据只作为条目依据出现，不单列验证流水。

第一轮（确认前，不下结论）：

```text
收尾清单
将直接执行
- <动作> → <依据>

需你选择
1. <对象、范围与目标环境>：<推荐项>（推荐，<理由>）/ <备选>

缺口（将记入 <落点>）
- <事实与证据> → <建议处置>
```

宿主有结构化提问工具时，「需你选择」用它发问。

第二轮（执行后）：

```text
结论：可结束 / 仍有阻塞

收尾结果
- <动作> → 已完成 / 按选择跳过 / 失败：<原因>

缺口列表
- <事实> → 记在 <路径> → <建议处置>

恢复入口：<一句话>
```

没有遗留事项时只报可结束，不创建额外报告文件。会话的交付回复仍应直接包含结果、验证和未解决项。

本 skill 由 agent 在准备交付或用户要求复盘时进入；客户端退出事件需要宿主 hook，不能由 skill 自身保证捕获。
