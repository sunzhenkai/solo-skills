# Session Wrap

收尾只盯三件事：**本次交付闭环了吗、现场收干净了吗、这次不做的事留痕了吗**。

默认分两轮：**第一轮只读自查，给简明清单等用户确认；第二轮按确认范围执行，用大白话报结果**。只要涉及写文件、改 git、停服务或外部操作，一律先确认再动手；完全无事可做时，直接告知可以结束。

`anti-lazy` 负责交付前查意图差距；`taskrail` 的 `close` 负责任务 SUMMARY、状态和归档。本 skill 面向整个会话兜底收尾，复用它们的产物，不重复造轮子。

## 1. 核对闭环与现场（只读）

只查和本次工作有关的真实现场，区分事实、推测和未知；纯问答或方案讨论只依据对话收尾，不扫描仓库。

- **目标与验证**：重读最初目标和最新要求，让每项明确要求对应到产物、回答或证据，区分已验证、未验证、未解决。原始场景和每项「必须」都要有结论；核心验收缺口留在本次处理，编译或静态检查不能替代原始场景验证。
- **代码交付闭环**（有代码改动时按序查到闭环）：
  1. 未验证 → 先补验。
  2. 有未提交改动或未跟踪文件 → 安排提交（执行时走 `commit-push`）。
  3. 在非默认分支且有未推送或未合入主分支的提交 → **必查收尾项**：已有 MR/PR 时核对 CI 与评审状态，不重复创建；尚无 MR/PR 时按 [references/branch-merge.md](references/branch-merge.md) 推荐「推送并提 MR/PR」或按仓库习惯合入主分支。
  4. 已合入或已提 MR/PR → 再评估清理 worktree 和临时分支（清理前先核对无未提交改动、无独有未推提交，未知文件保留）。
- **现场与任务状态**：核对本会话启动的临时服务、调试配置、后台任务和任务台账；`taskrail` 任务尚未收口时路由到 `taskrail` `close`。
- **遗留缺口与沉淀**：与本次目标无关但有证据的旧 bug、技术债、过时文档或环境隐患归为遗留缺口；跨任务有复用价值的内容按 [references/plan-synthesis.md](references/plan-synthesis.md) 路由到对应落点。排查绕过明显弯路（有死路、方向被纠正、根因出乎预料或明显超时）时，按 [references/detour-review.md](references/detour-review.md) 做弯路复盘，产出坑候选。

## 2. 汇总简明清单，等用户确认

把所有发现合成一张短清单，每个发现只出现一次，按依赖排序：**补验当前缺口 → 提交 → 推送与提 MR/PR 或合入主分支 → 任务收口与现场清理 → 缺口记账与知识沉淀 → 衍生处理**。

- **需要你拍板**：有两种以上合理做法，或涉及 git 写入、远端/共享分支、提 MR/PR、合入主分支、删除/清理 worktree、部署、写外部 tracker。每项一题，2–3 个选项，推荐项放首位并附一句理由；外部或不可逆动作一项一题，写明目标分支或环境。
- **准备帮你做**：本机、可逆、结论唯一的低风险动作（如把遗留缺口记入台账、停掉本会话启动的本地临时服务、归位临时文件、写入落点唯一的坑候选）。打包列出来，等用户确认后一起执行。
- **顺手记下的遗留（这次不做）**：超出本次目标的缺口，写明会记到哪里；本次只记账，用户点名才另开任务或处理。

动作分级、提问规则、缺口落点与知识分流表见 [references/plan-synthesis.md](references/plan-synthesis.md)。

## 3. 确认与执行

- **先确认后动手**：第一轮只做只读排查与列清单，所有写文件、改 git、停服务、外部调用一律等用户回复后再执行。即使清单里只有「准备帮你做」而没有选择题，也先亮出来等用户点头；只有完全无事可做时才直接结束。
- **授权隔离**：每项选择只授权该项，提交不等于授权 push，push 不等于授权合入主分支，合入不等于授权部署。执行中新发现加项或风险升级时，停下来再问一轮。
- **路由执行**：提交/推送走 `commit-push`，提 MR/PR 走 `repo-manager` 或 `gh` / `glab`（详见 [references/branch-merge.md](references/branch-merge.md)），任务收口走 `taskrail` `close`，知识沉淀走 `wiki-data` 或 `skill-upgrader`。

## 4. 面向用户的输出（说人话、短、好扫）

- **说人话**：用白话短句说清“差什么、建议怎么做”，把内部词（`criterion`、`落点`、`建议处置`、`恢复入口`、`合入通道`、`按选择跳过` 等）留在后台，直接转译成影响和动作。
- **控长度**：每条一行短句，空区块省略；路径和命令只在方便核对或恢复时顺带附上，不单列验证流水。第一轮尽量控制在半屏以内。
- **不重复**：宿主有结构化提问工具时，「需要你拍板」直接放进提问工具，正文只留 2–3 行现状与其余区块摘要，两边不重复列选项。
- **自然结论**：第一轮不下结束结论；第二轮开头用一句大白话交代现状（例如“可以收工了，MR !42 已提好等 CI”或“还不能结束，原始场景还没验证”），接着列出做了什么、什么没做、遗留记在哪。完全无遗留时只回一句可以结束，不生成额外报告文件。

正反示例见 [references/plan-synthesis.md](references/plan-synthesis.md)。

本 skill 由 agent 在准备交付或用户要求复盘时进入；客户端退出事件需要宿主 hook，不能由 skill 自身保证捕获。
