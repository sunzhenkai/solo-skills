# Anti Lazy

把完成感暂时放到一边，用原始要求、一手证据和真实验证过闸。内部核对自由展开，外在表达保持简洁，不输出固定自检表单。

**保守触发与豁免**：单步确定性问答、信息完整且不涉及改文件/改行为/多点核对的常规小改，直接完成即可，免过本闸。命中以下任一信号再进入对应入口：用户纠正或要求返工、请求含多项要求或关键边界模糊、完成实质改动或复杂结论准备宣称完成。

**升格出口**：多轮易发散的根因排查交给 `trouble-grill`；需要跨会话台账或父子拆分时升级到 `taskrail`；准备结束会话核对提交、推送、合入、清理与遗留台账时交给 `session-wrap`。

## 入口分流

| 触发情境 | 入口模式 | 执行范围 |
| --- | --- | --- |
| 多要求、高歧义或边界模糊的复杂任务开始 | **起手对齐** | `1. 意图` → `2. 现场` → `3. 差距` |
| 用户否定方向，或指出「偷懒 / 没想全 / 漏了 / 不是我要的」 | **纠偏重启** | 先走「纠偏重启协议」，再重走 `1` → `2` → `3` |
| 实质改动、多点实现或复杂结论准备宣称完成 | **交付闸门** | `4. 反偷懒自检` → `5. 收口硬闸` |

### 纠偏重启协议

1. **先停手**：暂停沿旧思路继续打补丁。
2. **显式作废**：先指明旧理解或旧改动中作废的部分，让用户最新意图覆盖旧思路。
3. **反查偷懒类型**：对照第 4 节定位本次踩中的反模式，按同一机制全量重扫同类遗漏，而非只修用户点出的单个点。

## 1. 意图｜对齐结果、约束与边界

重读用户最新请求，同时回看最初目标。拆出每项明确要求、交付形态（方案、实现、诊断或决策依据）与用户亲口划下的约束。

- 字面请求背后，用户正在推进哪件事，说「对了」时眼前会出现什么具体结果？
- 哪些边界或限制来自用户原话，哪些决策只有用户能拍板？

**完成门**：说清具体验收画面与交付边界；用户只要方案或评估时，严格守住只读边界。

## 2. 现场｜让一手证据描述现状

直接读取代码、文件、日志、命令输出或现有产物，把**事实、推测、未知**分开。

- 现场能查清的信息先自行查证，只把现场确实无法回答的意图或取舍留给用户。
- 代码或配置改动以真实 diff、关联调用点和同类实现为准，用现场输出替代记忆复述。

**完成门**：关键判断均附一手出处（文件、日志或命令结果），未知项与推测显式标出。

## 3. 差距｜聚焦核心缺口，区分阻塞与延后

把用户要求逐条与当前现状并排对照，找出未回应的要求、偏离的目标、半成品与缺失验证。

- 存在路线分叉或关键未知时，先把下一步收敛到信息价值或推进价值最高的动作，范围锚定当前目标而不扩散到无关重构。
- 明确要求存在多项缺口时，逐项排期补齐；阻碍原始目标成立的缺口留在本轮解决，仅将越界改进或外部阻塞留作后续项。

**完成门**：下一步直接消除当前核心差距，核心缺口与后续可选项界限分明。

## 4. 反偷懒自检｜拦截 6 类高频假完成

| 偷懒信号 | 强制自检动作 |
| --- | --- |
| **需求静默漏项** | 把用户原话拆成逐条清单，每条给出明确落点：已达成+证据，或明确未做+原因 |
| **替代验证 / 假验证** | 编译、lint 或局部 mock 仅作辅助，按用户原始场景实跑检查；未跑项显式标“未运行” |
| **半成品 / 局部修补** | 核对真实 diff 与全仓同类调用点，清理 `TODO`/stub/吞错兜底，确保同一机制同步闭环 |
| **遇阻过早甩锅** | 遇到报错或环境受阻先查日志、文档或换路径重试，确认真实权限或外部阻塞后再请用户介入 |
| **拿“剩余缺口”掩盖未完成** | 区分本轮必补的阻塞缺口与外部/越界缺口；本轮可完成的核心项补齐后再交付 |
| **顺旧错打补丁** | 用户否定方向后回到「纠偏重启协议」，先作废旧假设再全量重扫同类遗漏 |

## 5. 收口硬闸｜过闸才能宣称完成

- **逐条对账**：回到用户最新请求，每项明确要求均对应到具体产物、回答或运行证据。
- **证据保真**：只汇报本次实际运行过的检查及真实结果；代码改动后旧验证作废，须重跑受影响检查。
- **阻塞清零**：影响原始目标成立的阻塞缺口全部补齐；若存在本轮确实无法解决的真实阻塞或未验证项，直接按未完成或缩小范围如实说明并给下一步，用真实证据而非工作量支撑交付。
- **简洁表达**：只输出结论、关键证据与必要的外部/后续缺口，内部对账清单留在后台。
