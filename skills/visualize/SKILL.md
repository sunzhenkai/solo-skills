# Visualize

把给定内容变成读者一眼能看懂的图。本 skill 决定画什么、交给谁画、画得对不对；schema、布局和渲染由下游 skill 按各自当版正文完成，本 skill 只记录衔接所需的入口、目录和门禁。

边界：以文字为主的阅读页由 `pretty-ui` 的 page 模式承接；产品界面、页面与组件由 `ui-kit` 分派；项目架构的持久文档由 `project-atlas` 维护（它直接调用 archify）；演示文稿按 `ui-kit` 的演示路线。

## 主流程

每步达到完成标志再进下一步。

### 1. 定读者问题

读完全部输入，写出读者是谁、看完要回答的一个问题，以及回答它的一句结论。线性不超过三步、单个数字或纯定义，默认用文字或列表回答并说明理由；用户明确要求出图时仍按主流程画，交付时提一句文字已经足够。

完成标志：读者问题和结论句各一句；或已决定用文字回答并说明理由。

### 2. 写视觉简报

按 [references/brief.md](references/brief.md) 写 `brief.md`：选主形态，把要画的事实逐条列进事实清单并标出处，写明交付形态、约束和有意省略的内容。凭据、令牌、内网地址等敏感值在这一步换成占位符，多台主机按角色区分（`<db-host>`、`<internal-host-1>`）；简报、图和交付消息都不出现原值。画图必需的事实（日期、金额、规则、时间精度、统计口径）原文没有或精度不够时，向用户要，图里只放用户给出的值；用户也给不出时，按已知精度放置并标「不详」，或移入省略，并写进「读法」。下游字段留到第 3 步补写。

完成标志：图里要出现的每个标签、关系和数字都在事实清单里有出处。

### 3. 选下游

按 [references/routing.md](references/routing.md) 依「形态 × 约束」选定一个主下游，并探测它是否可用。不可用时沿降级链选下一项。降级会把以图为主改成以文字为主（落到 `pretty-ui` 阅读页或 Mermaid）时，先问一句：补齐运行环境，还是接受这次降级；推荐补齐，用户选定后再继续，其余降级直接进行。「读法」写降级原因和补齐方式：缺 skill 写 routing.md 的安装命令，缺 Node.js 写所需版本。安装经 `skills-store` 审计且得到用户同意后才执行。

完成标志：简报写明下游、图类型或页面形态，以及降级原因（如有）。

### 4. 交给下游执行

读取下游的 SKILL.md，按它的流程、门禁和修复上限执行；输入取自简报，输出目录由本 skill 指定。一份内容需要多张图时，每张图各用一个子目录，讲解页用相对链接指向它们。

完成标志：下游门禁通过，产物可在浏览器打开。

### 5. 核对与交付

按 [references/verify.md](references/verify.md) 做事实回查和看图：图中每个标签、关系和数字都对得上简报事实；无出处的删掉或标为推断，示意值在图上标明示意。回查不过时改下游源文件并重跑同一门禁；两轮仍不过就停下，报告卡在哪里。

完成标志：事实回查通过（有出处，或已标推断、示意、不详），看过画面或标明「未渲染验证」。

## 输出目录

优先级：用户指定路径 > 项目已有约定 > 当前工作目录下的 `visuals/<slug>-<YYYYMMDD-HHMMSS>/`。时间戳在请求开始时定一次，修复轮复用同一目录；新请求用新目录，旧版本保持原样。

```text
visuals/<slug>-<YYYYMMDD-HHMMSS>/
├── brief.md            # 视觉简报
├── <figure>/           # 每张 archify 图一个子目录：candidate.json、<figure>.html 与回执
├── <slug>.src.html     # visual-explainer 讲解页源文件
└── <slug>.html         # 讲解页成品
```

降级产物放同一目录：阅读页用 `<slug>.html`，只剩 Mermaid 时用 `<slug>.mmd`。截图拼版 `<slug>.sheet.png` 和 archify 的 `visual-check/` 是下游回执，随产物留在该目录。下游自带默认目录（archify 的 `.archify/`、visual-explainer 的 `~/.agent/diagrams/`）时，一律传入上面的路径。运行产物写在输出目录，本 skill 目录保持只读。

## 交付

用用户的语言，把结果说清即可。第 1 步决定用文字回答时，直接给文字或列表，加一句为何不画。

```text
[<描述性标题>](<产物绝对路径>)
<理解系统或方案类内容时，一两句要点>
读法：<抽象层级、有意省略、示意值、不详、降级原因与补齐方式>
核对：<下游门禁结果>；事实 <有出处>/<图中事实> 有出处，推断 <b>、示意 <c>；<已看图 / 未渲染验证>
```

「读法」没有可写的就省略。多个产物时给讲解页或首图链接，其余用简短列表。命令、修复轮次和回执细节留在输出目录，用户问起再给。

经验沉淀与正文演进走 `skill-upgrader`。
