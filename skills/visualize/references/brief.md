# 视觉简报

[visualize](../SKILL.md) 第 2 步读本页。简报是内容分析的唯一产物：下游只按它画，回查只按它对；换下游时复用同一份简报。

## 1. 模板

写到 `<输出目录>/brief.md`：

```markdown
# <标题>

- 读者：<谁；已经知道什么>
- 读者问题：<看完要回答的一个问题>
- 结论句：<一句话，作图标题或讲解页首屏>
- 主形态：<拓扑 / 流程 / 时序 / 数据流 / 状态 / 实体关系 / 类型契约 / 层级 / 时间线 / 耗时 / 对比 / 数量 / 概念讲解>；理由：<一句>
- 交付：<单图 / 讲解页>；下游：<archify `<type>` / visual-explainer / 降级：<下游>（<原因>）>
- 约束：<离线、语言、沿用的风格、导出格式等；没有写「无」>
- 输出目录：<路径>

## 事实清单

| ID | 事实 | 出处 | 必须 |
| --- | --- | --- | --- |
| F1 | <一个可画的单元> | <文件 §章节 / 第 n 条消息 / 数据列> | 是 |

## 省略

- <有意不画的内容>：<理由>
```

## 2. 字段写法

- **读者问题**只写一个。内容里有几个独立问题时拆成几张图，每张图一个问题，共用一份简报，事实清单按图分组。
- **结论句**陈述结论而非主题：写「缓存命中时请求不经过数据库」，而不是「缓存架构」。
- **主形态**按 [routing.md](routing.md) 第 2 节的「读者问题」列选；两种形态都说得通时，选读者问题里的动词指向的那个（「怎么流转」是状态，「先后顺序」是流程）。
- **事实清单**每条是一个可画的单元：一个组件、一条关系、一个步骤、一个状态、一个数字。关系写成「A 动词 B」，动词会成为连线标签。
- **出处**写到能回查的粒度：文件与章节、对话中的第几条消息、数据的哪一列。用户口述的补充写「用户补充」。
- **必须**标出读者问题离不开的事实；其余是可省略项，下游放不下时先省它们。
- **省略**写有意不画的内容和理由，交付时进入「读法」。

## 3. 内容来源的处理

- **文档、方案**：按章节提取组件、步骤和规则；文档里的示意数值保留「示意」标记。
- **对话**：只取已经确认的结论。被后续消息推翻的事实不进清单；作为对比对象的备选方案照常列入，并标注讨论结论。
- **数据**：数字保留原单位和精度。原文写了统计口径与时间范围就照录；没写就标「口径未知」，不追问。需要计算的（占比、增长率）在出处里写算法。
- **代码仓库**：组件和调用关系以源码为准，出处写文件路径；需要逐行证据的结构图交给 archify 的仓库证据流程。

## 4. 完成检查

- 读者问题、结论句、主形态和交付已填写；下游在第 3 步选定后补写。
- 图上会出现的每个标签、关系和数字都在事实清单里，且有出处。
- 敏感值已换成占位符，例如 `<REDACTED>`、`<internal-host>`。
- 原文缺失、必须由用户提供的事实已向用户确认。
