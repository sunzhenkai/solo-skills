# 核对

[visualize](../SKILL.md) 第 5 步读本页。下游门禁证明产物能渲染、结构合法；本页补上两件事：图里的内容是否忠于原文，画面是否真的看过。

## 1. 事实回查

1. 从下游源文件取出图里出现的全部文字：archify 看 `candidate.json` 的节点、关系、卡片、说明与图例字段；visual-explainer 看 `.src.html` 的标题、图注、SVG 文字和表格。
2. 逐条对到简报事实清单的 ID。对不上的按来源处理：
   - 原文有、清单漏了：补进清单并标出处。
   - 原文没有、属于推断：删掉；确需保留时在图上或「读法」里标为推断。
   - 示意数值：在图上标「示意」，并在「读法」里说明。
   - 纯排版文字（图例、分组名、方向词）：可以没有出处，但含义要与清单一致。
3. 反向检查：清单里标为「必须」的事实都在图上有位置；有意省略的已写进简报「省略」。
4. 敏感值：简报、产物和交付消息里都没有凭据、令牌、内网主机名或 IP，需要时用占位符，多台主机按角色区分。

完成标志：图中文字都有出处，或已标明推断、示意、不详；「必须」的事实无遗漏。核对行写「事实 <有出处数>/<图中事实数> 有出处，推断 <b>、示意 <c>」。标注为推断、示意或不详的项计入通过。

## 2. 看图

- archify：finalize 通过代表自动检查通过；按其截图流程看一遍首屏与整图，查重叠、裁切和看不清的标签。
- visual-explainer：看一遍 `.sheet.png`，确认首屏就是结论句，每张图陈述一个论点。
- 降级到 `pretty-ui`：按它自身的截图与检查要求。
- 截图或打开浏览器做不到时，核对行写「未渲染验证」。

## 3. 返修

问题出在内容（事实、标签、省略）时，先改简报，再改下游源文件；出在布局或渲染时，按下游的修复流程。每次修改后重跑同一门禁和本页回查。两轮仍不过时停下，报告失败的门禁、已尝试的修改和剩余问题。

## 4. 交付前清单

- [ ] 下游门禁通过（或降级路径的检查通过），非零退出按失败处理
- [ ] 事实回查完成，计数写进核对行
- [ ] 看过画面，或标明「未渲染验证」
- [ ] 产物都在输出目录，相对链接从产物所在目录可打开
- [ ] 降级、省略、推断、示意值和不详写进「读法」
- [ ] 简报约束逐条核对；要求离线时，产物不引用外部 URL（脚本、字体、样式）
