# 模式卡：模型供应商管理

> 应用如何从 models.dev 目录与自定义端点配置模型供应商实例、在添加/编辑时确定可用模型，并向全局默认模型、后台任务模型、会话切换等消费点提供两级联动选择。两处独立落地验证。

## 动机

LLM 应用常面临三类重复问题：
1. **供应商与模型列表硬编码**：上游新模型频繁发布，手工维护枚举极易过期；
2. **手填模型 ID 易错**：用户需要在多个输入框里盲输模型名，既无校验也无实时探测；
3. **消费点与实例脱节**：设置页的「默认模型」「任务模型」「对话切换」各自为政，切换 Provider 实例后模型列表不联动、甚至允许把 A 实例的模型配到 B 实例上。

## 参与者

| 参与者 | 职责 |
| --- | --- |
| 目录上游（`models.dev/api.json`） | 提供标准化的供应商元数据、协议 SDK（`npm`）、默认 `api` 端点与模型清单 |
| 目录同步与本地缓存 | 启动非阻塞 + 定时/手动刷新，内置离线快照兜底，记录同步时间与状态 |
| 供应商实例存储 | 持久化用户配置的连接：`catalog_id`（含 `custom`）、`api_format`、`base_url`、服务端密钥、`models[]`（实例已选模型白名单，首项为首选） |
| 实时发现与测活接口 | 基于草稿或已存实例凭据请求 `/models`（或 `/api/tags`）拉取实时模型并测试连通性 |
| 添加/编辑弹窗 | `来自 models.dev` / `手动配置` 双模式，智能填充 + 多选模型 + 测试连接 |
| 两级联动消费端 | 默认模型、后台任务模型、临时切换等选择器，严格从目标实例的 `models[]` 中取值 |

## 落地件（五件套）

1. **目录同步与离线兜底快照**：
   - 应用启动时若缓存为空先加载内置精简快照，不阻塞启动；后台异步检查 `synced_at`（如超过 24 小时）同步 `https://models.dev/api.json`（限制响应体大小与超时）。
   - 提供目录状态查询与手动触发同步接口（单飞防并发重入），同步失败保留旧缓存并记录错误摘要。
2. **供应商实例模型**：
   - 字段：`id`、`name`、`catalog_id`（目录 ID 或 `custom`）、`api_format`（`openai` / `anthropic` / `ollama` 等）、`base_url`、`api_key`（服务端保存，响应只返回脱敏掩码）、`models`（字符串数组，至少 1 项，首项为默认/首选模型）。
   - 更新实例时若 `api_key` 留空则保留原密钥；删除或修改模型列表不影响已有密钥。
3. **智能自动填充与协议路径投影**：
   - 按 `npm`（如 `@ai-sdk/anthropic`）与供应商 ID 推断默认 `api_format`。
   - 端点自动填充优先级：按 `(catalog_id, api_format)` 已知双协议端点表 → 目录 `api` 字段（含 `.../anthropic[/v1]` ↔ `.../v1` 路径投影）→ 已知默认端点兜底表。
   - 使用 `touched` 标记保护用户手动编辑过的 `name` 和 `base_url`，不再被后续选择覆盖，并提供「使用目录默认值」一键重置。
4. **双源模型候选与草稿测活**：
   - 模型候选 = `models.dev` 目录该供应商模型 ∪ 端点实时 `/models` 拉取结果（目录顺序优先、去重）；输入不存在的 ID 时允许显式添加自定义模型。
   - 弹窗内即完成「要使用哪些模型」的多选勾选与首选排序（至少选 1 个才允许保存），并提供「测试连接」按钮（编辑态未改地址和密钥时自动复用已存凭据）。
5. **消费端两级联动选择器**：
   - 所有模型配置点（默认模型、后台任务模型、对话内临时切换等）均采用「实例 → 模型」两级联动。
   - 模型下拉选项**严格来自所选实例的 `models[]`**，禁止跨实例选择或自由手填未登记模型。
   - 切换实例时自动联动：若目标实例也包含当前模型则保留，否则自动选中目标实例的首选模型（`models[0]`），并一次原子提交 `(instance_id, model)`。
   - 可选支持「沿用默认」选项（如后台任务模型）：选「沿用默认」时清空任务级实例与模型覆盖并禁用模型下拉。

## 边界

- **密钥安全**：API Key 永不回传前端；列表与详情仅返回掩码；编辑留空保持不变；实时 `/models` 发现与测活均由服务端代理发起，避免浏览器 CORS 与密钥暴露。
- **网络策略按部署形态分档**：
  - 公网/多租户 SaaS：严格限制 `https://` 且拦截内网/回环 IP（防 SSRF）；
  - 本地/局域网个人应用：放行 `http://` 与内网地址（支持本地 Ollama 及局域网网关），但拒绝含 `${ENV}` 模板段或非 HTTP 协议的 URL。
- **离线可用**：`models.dev` 不可达时，内置快照 + `手动配置` 模式始终可用，不阻断核心配置。
- **数据一致性**：消费点只选实例内已勾选的 `models[]`；服务端校验 `models` 非空字符串数组、去重并限制上限（如 64 个）。

## 先例

| 应用 | 目录来源与协议 | 实例选型与消费端联动 |
| --- | --- | --- |
| 通用 Agent 平台 | `models.dev` 24h 同步 + `provider-catalog`；`openai-compatible` / `anthropic`；公网 HTTPS 校验 | 连接内选默认模型 + 允许列表 `models[]`（上限 64）；连接列表与运行时路由按连接约束校验 |
| llmwiki | `models.dev` 启动/24h/手动同步 + 内置快照兜底；`openai` / `anthropic` / `ollama`；允许本地 `http://` | 实例多选 `models[]`（首项为首选）；「默认模型」「摄入任务模型（含沿用默认）」「对话切换」均严格从实例 `models[]` 两级联动 |
