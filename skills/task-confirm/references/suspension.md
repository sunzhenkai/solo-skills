# 挂起子协议（等用户的统一形态）

凡「需要用户产生的输入才能继续」的点——退出点已列的授权、复杂档降级确认、
危险操作点名、详细设计裁决——停下时按本协议呈现与等待。本文件是族内通用
定义：`task-confirm` 直接使用；taskflow、taskrail 等引用本文件，
不各自发明「停下」形态。

## 挂起五元组

停下等待的回复必须写全五项，缺一项不算进入挂起：

1. **等待项**：等的是哪一个决定（一句话，对应退出点标签或已列授权项）。
2. **授权形状**：用户说什么算数——逐字可判的话（如「降级全部接受」
   「点名接受第 N 项」「仍按此方案执行」）。授权是封闭集合，不发明新授权项。
3. **阻塞面**：等待期间不能做什么（改方案、写交付代码、commit/push、
   交接、标完成——按命中的退出点取）。
4. **非依赖面**：等待期间仍可继续做什么（见下「合法动作白名单」）；
   全部工作都依赖该决定时写「无」，不硬凑。
5. **恢复触发**：什么事件使重评估——用户消息到达先比对授权形状；
   命中即按授权走，未命中重申仍停（不写成选项列表）。

## 合法动作白名单（挂起期间）

允许且应做：只读环境查证、外部原文取证、证据固化、与等待项无依赖的
既定工作。审阅类等待（退出点为审阅派不出 / 审阅没有结论）额外允许
重试派审——审阅者只读；派审成功即按审阅收敛 / 审阅未收敛处理，该
等待自动解除。禁止：交付代码、改完成判据/步骤/降级表、commit/push/
部署、把挂起包装成进展。

## blocked（挂起的交接形态）

同一等待项被 goal 自动续跑连续第三次且仍无用户输入：标记 blocked，
给交接摘要四段——已完成、未完成、证据、下一步（下一步写授权形状里
那句话）。给出摘要的同一轮把四段写入 state-file 的 `handoff_summary` 字段并落盘 `blocked: true`（schema 见 [state-file.md](state-file.md)）；后续轮只读该字段，不重算。blocked 不是新状态，goal 留在已停。无自动续跑的环境
（非 goal 模式）：首次停下即按五元组呈现，不空等第三轮才给摘要。

「下一步」按**最小解除集**排序：一句授权能同时解掉最多退出点的
排最前，并写明这句解掉哪几个退出点；逐条解的排后。多个等待项时
先给最小解除集，再给完整清单。

## 恢复

恢复触发到达后：先核对授权形状，再按对应状态格走；恢复回复第一行
写清「等待项 → 已解除/仍未解除」。挂起期间固化的证据在恢复时直接
引用，不重做。
