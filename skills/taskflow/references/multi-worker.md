# 多 worker 并行（附录）

默认串行；只有宿主有多 agent 能力、且有至少两个无未完成依赖的单位时才读本附录并行。并行不改变进度真源，片间检查点仍由主会话统一核对。

## 可以与不可以

| 可以并行 | 必须串行 |
|---|---|
| 只读 explore / review | 同一任务同一仓库的代码写、测试、git index 与提交 |
| 不同子任务 | 有未完成依赖或共享契约未冻结的单位 |
| 不同修改仓的独立实施 | driver 编排项、父 TASK、收尾回归与归档 |

不再让多个写 worker 仅靠“文件不重叠”共享一个 worktree。需要同仓写并行时第一版直接串行；不要临时发明 worker 分支和集成协议。

## 派发与回收

- 先冻结接口、类型、共享组件和目录契约；改共享面先广播受影响的 worker，新交付形态样板先行，验收后再铺开。
- 每个 worker 只领一个单位，输入含 criterion、负责范围、必要契约、worktree 绝对路径和证据要求；不给完整历史、兄弟子任务或无关评审。
- worker 只写自己代码与证据，不写父 TASK 或 driver 编排项；主会话汇总并更新状态。
- 返回只有结论、修改 / 验证摘要、路径和未决；原始日志留文件。
- 两个以上 worker 出现同类失败时停并行，回 diagnose / design；一个 worker 失败不终止其他就绪项。
