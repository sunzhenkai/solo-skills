# Way To Fix

把问题从症状推进到根因、最小修复和防复发检查。深度花在证据上，简单问题走最短路径，复杂问题再增加排查强度。

## 边界与协作

- **职责与升级**：本 skill 负责单问题修复闭环。需要跨会话台账、多阶段或跨仓拆分、worktree 编排时升级到 `taskrail`；多轮或易发散的根因排查使用 `trouble-grill`；交付前用 `anti-lazy` 核对原始要求与证据；修复后的提交、推送与合入收尾按需交给 `commit-push` 或 `session-wrap`（绕过明显弯路时可做弯路复盘）。
- **只读与写边界**：排查与复现默认只读；确需写临时脚本或调整验证环境时保持隔离、可逆，并在收尾时清理。用户只要分析或方案时保持只读交付边界；用户要求修复时仅实施当前问题所需的本地改动。
- **确认与授权隔离**：涉及修改公共接口、配置或错误语义、新增依赖、扩大到同类问题，或触及共享、线上环境与外部系统时，先取得用户确认再动手。允许修复仅覆盖本地改动与验证，git 提交、推送、合入主分支与部署均需另行确认。

## 1. 分析问题：让症状可观察

- 用用户原话和现场证据写清期望行为、实际症状、发生条件与影响范围；版本和环境在影响判断时记录。
- 先检查已有测试、日志、监控、相关代码、近期变更与工作区既有经验库（有 `wiki-data` 时按现象词走其 `query` 预检），优先复用现有入口建立最小复现。性能退化记录基线、样本和指标。
- 区分事实、推测和未知；同时排查环境错配、过期构建或瞬时工具与网络故障，将其与代码缺陷分开处理。检查要捕捉用户的原始症状，而非仅验证程序能够运行。

**完成门**：得到能捕捉原始症状的复现或观测信号，并记录实际运行的命令或检查及关键结果。无法复现时，写清已试范围、现有证据和下一项最有信息量的动作，后续结论保持相应置信度。

## 2. 找到根因：建立因果链

- 沿调用、数据或配置链，从症状追到触发条件和失效机制。每个解释写出可观察预测，用能区分解释的动作验证，每次只改变一个变量。
- 直接证据已指向原因时做最小确认；多轮、易发散或假设反复被推翻时，使用 `trouble-grill` 的锚点、假设板与四道门。
- 准备修复且有合适测试缝时，先将最小复现固化为回归测试，在未修复代码上观察失败作为因果锚点。可行时在安全可逆的验证环境中做反事实确认：移除疑似原因后症状消失，恢复后症状复现。
- 同一思路连续两轮没有新证据时，换用日志、测试、官方文档或用户信息等新信息源；仍无进展就停下，报告阻塞点与已试方法。

**完成门**：根因表述包含触发条件、失效机制、症状和证据，并能解释关键观察。证据不足时输出候选方向、置信度、证据缺口和下一验证动作，将其与已确认根因明确区分。

## 3. 给出方案：最小修复并验证

- 在离根因最近的位置实施最小修复，直击失效机制而非用吞错或宽容兜底掩盖症状；保持现有接口、配置和错误语义。每处变更对应根因或回归验证，发现的其他改进列为可选后续。
- 默认给出一个推荐方案；兼容性、风险或成本存在真实取舍时再比较备选。复用项目已有实现和测试缝，新增抽象或依赖需要当前问题的直接证据，并先确认变更边界。
- 用户只要方案时，写清修改位置、关键改动、验证命令和预期结果。用户要求修复时，修改后观察此前失败的复现或回归检查转为通过，保持原有测试断言强度，再复测原始未简化场景与相关现有检查，并清理临时调试内容；缺少合适测试缝时，使用覆盖真实调用链的检查并说明验证边界。
- 修复后检查仍失败或引入新回归时，先核对或回退本次改动，把新失败作为反证回到第 2 步重查根因，持续收敛而非堆叠补丁。

**完成门**：方案交付以可执行步骤和明确验收为完成；实施交付以原始症状消失、回归检查和相关检查通过为完成。失败、中断和未运行项连同原因随结果说明。

## 4. 举一反三：检查同一失败机制

- 以失败机制而非相似文本界定同类风险，检查受影响组件、兄弟实现和直接调用点；搜索命中只作为待核实线索。
- 优先让最小复现覆盖同类输入或边界，沿用现有测试结构，使一个回归检查覆盖整类已确认问题。
- 列出其他已核实问题的证据、影响与建议范围，扩大修改范围前取得用户确认。
- 可复用结论写成「发生条件 + 失效机制 + 识别方法」。用户要求沉淀或项目已有明确约定时，再写入对应知识库（有 `wiki-data` 时交给其 `ingest`）。

**完成门**：给出同类检查的范围与结果，区分已证实缺陷、待核实线索和已排除项，并说明回归检查覆盖的类别与剩余盲区。

## 交付

- 用白话短句结论先行，按「问题与证据 → 根因与置信度 → 方案或改动与验证 → 同类检查与剩余风险」组织，只输出有内容的区块并省略空段，让每项明确要求对应产物、回答或运行证据。
- 只呈现关键证据、验证盲区与必要的回滚说明，内部假设板和试错过程留在后台；简单问题直接合并为结论与验证两句。
