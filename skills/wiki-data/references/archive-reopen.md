# archive 与 reopen

原则：原地标记、保留历史、隔离当前查询、显式恢复。归档对象是整份业务页；单次问答保存仍走 `query`，新知识摄入仍走 `ingest`。

## 边界

- 页面保留原路径与 `type`，不建物理归档目录，既有链接继续有效。
- `raw/`、系统页与既有历史保持原样；`wiki/log.md` 只追加。
- `experience.status` 继续表示验证状态，`ledger.status` 继续表示业务状态；归档由独立字段表达。
- 归档页不再产生 `review_overdue`；原复审日期保留，重开时重新核实。

## archive

1. **核对影响**：读目标页全文，检查入链、替代页、未决冲突与来源。归档原因可以是整页被替代或不再适用；替代页不是必需项。
2. **展示计划**：列出目标页、原因、替代页（如有）、受影响入链和未决冲突，确认后再写。
3. **原地标记**：frontmatter 写入：
   ```yaml
   archived_at: YYYY-MM-DD
   archive_reason: 整页归档原因
   superseded_by: "[[替代页面]]"  # 可选
   ```
   `archived_at` 存在即表示已归档。更新 `date`，保留 `title`、`type`、`created`、`sources`、`confidence` 与原有核实字段。
4. **保留历史**：在正文「归档与重开记录」下追加日期、原因和替代页；已有该章节时追加，不覆盖旧记录。
5. **处理入链**：活跃页仍可因历史追溯链接归档页，但须明确历史语义；作为当前依据的链接改指替代页或补充现行结论。
6. **收尾**：回读页面，运行 `lint_wiki.py --write-index`，追加 `## [YYYY-MM-DD] archive | <页面与原因>`。

完成门：元数据完整、历史与来源保留、索引已归入「已归档」、日志已追加、lint error 为 0；`archived_reference` warning 已处理或说明为有意保留的历史链接。

## reopen

1. 用户明确要求恢复后，读归档页全文、归档记录、替代页与相关入链，说明重开原因。
2. 重新核实拟恢复的主张、来源和适用范围，按当前证据更新 `confidence`、`last_verified` 与必要的 `review_after`；未核实主张保持低置信度，不因重开自动成为当前事实。
3. 先处理原替代页关系：合并两页、写清各自适用范围，或归档其中一页；不能留下两个回答同一当前问题却关系不明的活跃页。
4. 在「归档与重开记录」追加重开日期、原因、核实结果和替代页处理；移除 frontmatter 的 `archived_at`、`archive_reason`、`superseded_by`，更新 `date`。历史记录继续保留。
5. 回读页面，运行 `lint_wiki.py --write-index`，追加 `## [YYYY-MM-DD] reopen | <页面与原因>`。

完成门：归档标记已解除、当前主张已重新核实或降级、替代页关系明确、历史记录完整、页面回到对应类型的当前索引、日志已追加、lint error 为 0。
