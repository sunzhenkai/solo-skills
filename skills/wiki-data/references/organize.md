# 重组

合并重复、搬页、补交叉引用。先给方案，确认前不改。

写页时读 [page-types.md](page-types.md) 的实体/概念边界。改完读 [lint.md](lint.md)。

## 步骤

1. 跑 lint，按真实输出描述结构；只描述 lint 实际报出的目录（如没有 `wiki/entity/`、`wiki/skills/` 就不提）。
2. 识别：重复页、孤立页、错位、实体-概念耦合、缺失反链、可归纳为排查模式的坑。
3. 给出方案（合并 / 移动 / 补链 / 拆名 / 归纳模式）。确认前不改。
4. 执行前读所有受影响页。合并必须保留双方独有信息。
5. 再跑 lint；更新 index；结构变更追加 `## [YYYY-MM-DD] organize | …`。

## 归纳排查模式

至少两个活跃的 `kind: pitfall` 页共享同一类误导信号或同一个最短判别时，在方案中提议新建或更新一页 `kind: pattern`：

- 标题用中性的机制或规律名，不含具体系统名；`symptoms` 写跨实例的通用现象词。
- 「触发信号」写跨实例的现象组合，「最短判别」写可以先做的通用判别，「误判与弯路」汇总共同的误判，「证据」与 `related` 列出全部实例。
- 实例页在 `related` 回链模式页；实例自身内容留在原页，不搬进模式页。
- 模式页默认 `status: draft`；之后有新实例按其「最短判别」命中并验证，再改为 `validated`。
- 只有一个实例时不建模式页，在坑页的「边界与失效条件」记下候选规律。
