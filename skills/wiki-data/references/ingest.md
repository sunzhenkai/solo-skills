# 摄入

把一份本地材料或当前对话中的可归档信息编译进 wiki。一次 ingest 通常会动多页：源摘要 + 若干实体/概念/经验/台账 + 交叉引用。

## 输入

优先顺序：用户指定的本地文件 → 粘贴文本 → 当前对话中的可归档信息。

`project-explore` 的 ExplorationBrief、持久化建议和 Atlas 回执可作为当前对话中的候选材料；仍需按本页拆分归属、搜索既有页并展示归档列表，不把这些交接内容视为已批准写入或替代 `sources`。

不要主动去抓任意 URL。用户明确给出链接并要求纳入时，先确认范围再取回文本。

大文件按章节或自然段分块，每块仍绑定同一来源。

## 上下文自动提取

用户要求从当前对话或上下文摄入时，主动回顾可见内容，自动完成「提取候选 → 保存计划 → 按确认范围落地」，无需用户逐条点名。自动仅指候选提取与保存计划；普通对话不在后台摄入，写盘仍遵守范围确认与隐私门禁。

「有用」以 `purpose.md` 的范围和后续复用价值判断：能回答关键问题、支持后续决策或执行、追踪重要状态，或保留可追溯证据。重复内容、客套、一次性中间过程和无后续价值的细节不纳入；重要但证据不足的内容可保留为低置信度候选或开放问题，不写成当前事实。

提取时覆盖以下方面，并复用既有页面类型：

- **知识与主题**：事实、实体、术语、方法、框架、机制、关系和主题，按内容归入 `entity` / `concept`。
- **经验与踩坑**：保留适用条件、触发信号、现象、证据、预防处理、验证结果与边界，归入 `experience`；未确认的原因保留为假设或开放问题。
- **操作、决策与状态**：保留值得记录的操作、决策内容、理由、取舍与状态变化。业务对象的当前状态与历史归入 `ledger`，单次决策与依据保留在 `source`，可复用原则归入 `concept` / `experience`。
- **对比与综合**：方案或对象的异同、结论与依据归入 `comparison`；跨来源归纳和开放问题归入 `synthesis`。
- **来源与问答**：单次材料摘要归入 `source`；有长期复用价值的问答归入 `query`，开放问题也可留在相关页的后续问题中。

合并同一事实的重复候选，区分已证实事实、用户决策与未验证推测。敏感信息按 `<REDACTED>` 或拒绝该段处理，不写成明文。

材料同时包含当前系统行为与知识上下文时，先拆分归属：架构、业务流程和规则的现行说明交给 `project-atlas`，不转成 wiki 的 `entity` / `concept` / `synthesis` 正文；决策理由、备选方案、经验、台账和来源摘要仍按本页摄入。需要建立或更新 Atlas 时先完成该工作，再按已确认的归档列表写 wiki；两个工作区分别遵守各自的写盘确认。

先向用户展示**归档列表**，再按列表摄入。归档列表即保存计划，每项列出：摘要、保存价值（未来用于什么）、候选 `type`、新建 / 更新 / 合并目标、上下文证据（原话要点或来源）、拟定置信度、核实日期与复审日期（如需要）。计划末尾列出**不纳入项及理由**，如重复、越界、一次性细节或无后续价值。归档列表即本次写入范围；后续发现遗漏时先补充列表再写。既有范围确认与隐私门禁不变。

## 排查记录

用户明确要求归档 `trouble-grill` 记录时，按本页流程摄入，保留锚点、证据等级、用户输入、路径（含 `dead-end`）、验证盲区与回退条件。

- 整份排查记录先写 `wiki/sources/` 摘要；跨来源归纳时再写 `wiki/synthesis/`；形成可复用做法时再写 `wiki/experiences/`。
- 只有 `confirmed` 假设可写成根因；其他等级保留为线索或开放问题。
- 归档范围以用户确认的排查记录为准。

## 经验与台账

- 经验页写可复用结论，不只复述一次事件。保留适用场景、触发信号、预防与处理、验证方式、证据、边界与失效条件，让下次执行前能直接生成检查项。
- 证据不足时用 `status: draft`。只有「验证方式」已有对应结果和来源时才改为 `validated`，同时记录 `last_verified` 与 `review_after`；状态不替代 `confidence`，仍按证据强度定级。
- 失效经验改为 `deprecated`，写明失效条件、日期、依据和替代页链接，保留历史来源。纠正其他页面时保留旧主张并标「已更正」、日期、新来源与替代结论，避免旧文本继续以未标状态的现行事实出现。
- 一个业务对象对应一个 ledger 页。更新时先读全文，同步 frontmatter `status` / `date` 与「当前状态」，记录本次 `last_verified`，再在「历史」追加带日期的变更；纠正历史也追加新条目，不改写旧条目含义。
- `wiki/log.md` 只追加本次 wiki 操作，不承载业务对象状态。

## 步骤

1. **读材料**，列出候选实体、概念、经验、台账、关系与主张，并标出应交给 Atlas 的现行系统内容；从上下文摄入时按「上下文自动提取」覆盖全部候选类别。
2. **范围与隐私**：超出 `purpose.md` 先告诉用户。发现凭据、个人隐私、内部主机名则停止写入明文，改用 `<REDACTED>` 或拒绝该段。
3. **搜索已有页**：对每个候选名跑 `rg`（含 `aliases`、缩写、中英变体），同时发现活跃页与归档页。读命中页，避免重复建页；命中归档页时，在计划中说明是新建替代页、重开旧页还是仅追加历史来源，不直接把新事实合入归档页。
4. **归档列表**（对用户可见，写盘前完成；复杂时先确认再写）：
   - 每项的摘要、候选 `type` 与上下文证据
   - 每项的 `confidence`、证据日期、`last_verified` 与易变内容的 `review_after`
   - 新建哪些 typed 页
   - 更新或合并哪些旧页（新事实 / 必须保留的旧事实 / 将追加的链接）
   - 被新页整体替代的旧页及其归档原因、替代链接
   - 对应的 `wiki/sources/` 摘要
   - 需交给 `project-atlas` 的现行系统内容，列入不纳入项，不在 wiki 重复保存
5. **按归档列表执行**，先写源摘要到 `wiki/sources/`，填写 `origin`、`captured_at`、指向 raw 的 `sources` 与可选 `content_hash`，记录关键主张、提到的实体/概念、后续问题。对话或粘贴材料分别使用 `conversation` / `user-input` 作为 origin，并同样建立来源页。
6. **写或合并业务页**。默认写入 `{WIKI_ROOT}/wiki/` 下对应 typed 目录，填写 `description`、必要的 `aliases` 和非空 `sources`。按 page-types 的证据标准设置页面默认 `confidence`，不同证据强度的主张逐条标注；`high` 必须有本次或既有 `last_verified`，易变知识必须给出 `review_after`。更新旧页时：
   - 先读全文
   - 锁定 `type` / `title` / `created`
   - 数组字段并集去重
   - 正文整合新事实，不覆盖旧段；冲突并列并标明来源、时间与适用范围，未裁决的主张保持低置信度
   - ledger 的「历史」只追加，经验状态变化保留依据
   - 新页整体替代旧页时，按已确认范围走 archive，保留旧页历史与双向链接
7. **交叉引用**：相关页加 `[[wikilink]]`；实体-概念关系写在正文，不拼进概念标题。当前项目实体对应已有 Atlas 时，在正文加指向 Atlas `index.md` 的相对 Markdown 链接；链接仅作导航，不替代 `sources`。命名规则见 [page-types.md](page-types.md)。
8. **验证**：回读新页；运行 `lint_wiki.py --check-index`；来源、歧义链接、索引等 error 必须修，warning 说明后处理或有意推迟。
9. **簿记**：用 `--write-index` 重建 `wiki/index.md`，再跑 `--check-index`；`wiki/log.md` 追加一行；必要时改 `wiki/overview.md` 的主题/状态，不要删旧综述。

## 合并时不要做的事

- 为了「干净」丢掉旧 `sources` 或旧事实
- 用新标题覆盖身份字段
- 把 raw 文件改写成 wiki 页
- 把源摘要写进实体/概念页而不建 `wiki/sources/` 页
- 在 `wiki/templates/` 下写业务内容

## 完成标准

- [ ] 上下文摄入已先展示归档列表，实际写入与列表一致
- [ ] 材料中的关键实体、概念、经验和台账都有页（或已说明为何合并到旧页）
- [ ] 相关页有 `[[wikilink]]`；本轮涉及已有 Atlas 的项目实体页已按需添加导航链接
- [ ] Atlas 所属的现行系统说明未复制进 wiki
- [ ] 已搜索、无重复建页
- [ ] 业务页 frontmatter 含 title / type / date / confidence / description / sources，经验与台账含 status，source 含 origin / captured_at；所需核实与复审字段齐全
- [ ] 主张级例外已标置信度，冲突、纠正与失效内容保留来源、日期和状态
- [ ] 经验含触发信号、预防与处理、验证方式；validated 有对应验证证据
- [ ] 文件类摄入有 `wiki/sources/` 摘要
- [ ] 旧页保留原有信息与来源，台账历史只追加
- [ ] 已回读并跑 lint，error 为 0
