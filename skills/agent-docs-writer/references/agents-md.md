# 编写 AGENTS.md / CLAUDE.md

在 `instructions` 路径使用本细则。AGENTS.md 是自动加载的项目工作约定；详细方法与按需资料通过明确指针加载。

## 1. 确认作用域与现有层级

先定位仓库根、目标目录和现有的 agent 指令文件，确认目标运行时的发现与覆盖规则。通常根文件承载共用约定，离目标目录更近的文件承载局部差异；具体行为以实际工具文档为准。

检查同目录的 `AGENTS.md`、`CLAUDE.md`、软链及项目约定，保持一个权威来源。用户点名特定文件或副本策略时遵循其要求。

完成标志：目标文件、影响目录和上下级关系已明确。

## 2. 从仓库提取事实

按需要读取最小证据集：

- 包管理与锁文件：运行时、包管理器、依赖安装方式。
- 项目清单和脚本：启动、构建、测试、lint、格式化命令。
- CI 与贡献文档：交付门禁、分支、提交或评审约定。
- 目录与配置：非显而易见结构、代码风格、生成物和危险区域。
- 已有指令与历史纠正：仍需保留的隐性约定及其原因。

命令必须来自可定位的来源；推测的写法标为待确认。格式化和静态约束能由工具直接执行时，优先给出工具命令，而不是复述一整份规则。

完成标志：计划写入的每条命令和项目事实都能追溯到文件、配置或用户确认。

## 3. 编写持续有效的指令

按项目实际需要选择章节：

1. **项目地图**：只解释帮助定位工作的结构和职责。
2. **运行与检查**：给出准确的安装、启动、构建、测试和 lint 命令，以及必要的执行目录。
3. **工程约定**：记录工具无法表达、源码又看不出的约定及原因。
4. **变更边界**：说明生成物、共享配置、敏感数据和需额外授权的操作，同时给出安全默认路径。
5. **完成标准**：说明需要运行哪些检查、怎样验证用户场景、如何报告未运行项。

根文件保留通用约定，嵌套文件只写局部差异。通过指针引用按需文档时，写清任务或条件，例如“修改 API 契约时读取 …”。已有文件采用最小编辑，保留仍有效的内容并更新已经失效的描述。

完成标志：新 teammate 能据此运行项目和验证改动，且每条规定都适用于其所在目录。

## 4. 验证加载与可执行性

- 检查文件位置、软链、嵌套覆盖和引用路径。
- 运行与本次改动相关的安全本地命令，记录真实结果；可能修改共享环境或产生不可逆影响时先停下确认。
- 工具支持查询指令来源时，确认目标文件确实被加载。
- 检查新增内容是否与上下级指令重复或冲突。

完成标志：作用域和命令均有验证证据；无法执行的命令已注明原因和剩余风险。
