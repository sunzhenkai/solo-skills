# Agent Docs Writer

把真实工作方式沉淀为 agent 可发现、可执行、可验证的文档。交付以目标 agent 的实际行为为准，Markdown 完整只是其中一项。

## 路径选择

| 路径 | 进入条件 | 写入行为 | 完成标志 |
|---|---|---|---|
| `skill` | 从零创建 Skill，或把可复用工作流提炼成 Skill | 用户要求创建后写入 | 新 Skill 结构完整，触发与执行案例经过检查 |
| `instructions` | 新建或更新 `AGENTS.md` / `CLAUDE.md` | 用户明确要求写入后编辑 | 指令来自仓库证据，作用域清楚，相关检查已运行或标明缺口 |
| `review` | 评审、审计或诊断已有 agent 文档 | 只读 | 每项发现都有位置、影响与可执行建议 |

已有 Skill 的正文或配套修改交给 `skill-upgrader`，沿用其 patch 审计流程；`agent-docs-writer` 负责从零创建和只读评审。用户同时要求评审与修复时，先完成 `review`，再按目标类型进入对应写入路径。

进入路径后读取对应细则：

- `skill` → [references/skill-authoring.md](references/skill-authoring.md)
- `instructions` → [references/agents-md.md](references/agents-md.md)
- `review` → [references/review.md](references/review.md)

## 共用主流程

### 1. 确定交付契约

从对话和现场提取目标路径、文档类型、新建或已有、读写范围、预期行为和完成条件。信息已经足够时直接推进；只有会显著改变产出的未知项才向用户提问。

完成标志：能用一句话说明“为哪个使用场景，交付什么文件，怎样算有效”。

### 2. 收集最小证据

优先使用当前任务中的真实操作、用户纠正、输入输出和已有文档；仓库指令以实际配置、脚本和 CI 为准。读取范围随当前问题收敛，不为 hypothetical branch 预先搭建结构。

完成标志：关键行为均有来源，尚未证实的内容已标为假设。

### 3. 选择信息落点

- 跨任务复用的方法进入 Skill。
- 仓库持续生效的规则、命令和边界进入 AGENTS.md。
- 仅特定分支需要的细节进入有明确触发条件的 reference。
- 环境已经准确表达的事实留在原配置或文档中，通过指针使用。

完成标志：每项内容只有一个权威落点，主文件只保留每次运行都需要的路由、步骤和门禁。

### 4. 起草最小可用版本

让 description 和其他指针写清内容与触发分支；让步骤带可检查的完成条件；让输出模板、条件和默认方案直接表达目标行为。环境提供 `writing-for-agents` 时，用它辅助写作与剪枝；未提供时按本 skill 的门禁继续，不增加安装依赖。

写入前说明目标文件与变更范围。用户已经明确要求创建或更新时直接执行，保留无关内容，不顺手重排整个文档。

完成标志：目标文件覆盖已确认场景，引用可从主文件一层直达，且没有等待补充的占位内容。

### 5. 验证实际作用

执行当前路径细则中的静态检查与行为案例。能运行时记录命令和结果；缺少独立执行环境、工具或必要输入时，明确报告未验证项，不用文本评审冒充行为验证。

完成标志：每项验收标准都有通过证据或明确的未通过原因。

### 6. 交付与收口

报告文件清单、关键决策、验证结果、假设和未解决项。创建提交、推送或安装到共享位置前，另行取得用户要求。

## 公开分发与安全

示例采用通用、虚构的数据和相对路径。凭据、内部地址、私有项目内容与真实任务痕迹留在使用者的私有工作区。运行产物写入用户指定位置或工作区既有产物目录，安装后的 skill 目录保持只读。
