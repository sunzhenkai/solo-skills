# 意图确认细则

## 1. 探索（详细、只读）

要摸清的上下文：

- **现状**：相关代码 / 配置 / 文档的现状与入口；现在怎么工作、哪里不满足。
- **约束**：技术约束、接口与兼容性、时间或资源限制、用户原话里的禁止项。
- **已有工作**：`tasks/` 下相关任务与 ADR、近期提交、已有方案或失败尝试。
- **歧义**：原话里哪些词有多种读法、哪种读法会改变做法。
- **外部参照**（按需）：选型 / 集成 / 协议对接时看一眼业界做法。

面广时可并行派只读 subagent 分头摸（交代目标、输入、只读、详情落 `evidence/intent/<主题>.md`），只回简短摘要（结论 + 证据路径 + 未决）。主会话不转贴全文。

## 2. 覆盖清单（内部用，不照着打印）

复述前自查这 7 项都想清楚了；它们写进 `wizard/intent.md`（见第 6 节），**不**逐项打印给用户：

要干嘛（含为什么）· 怎么干 · 输出什么（含做完的样子、落在哪）· 上下文（现状、约束、已有工作）· 不做 · 我的假设 · 要你拍板的（最多 1 个，带推荐）

## 3. 给用户的复述（自然口语）

- 1–3 句话，第一人称，像同事口头确认：自然带出做什么、怎么做、产出什么、落在哪。
- 上下文、假设、不做的事：只在会影响结果时顺带一句，不用就不提。
- 结尾说接下来会发生什么（如「写完告诉你放在哪」）。
- 最多一个问题，自然嵌在句子里，并带上你的推荐。
- 不要标题、不要加粗标签、不要逐字段列出（通用规则见 taskrail 契约「对用户说话」）。

示例：

- 好，我按仓库的约定挑个合适的位置写成一份文档，内容包括流程图、各 skill 的分工、两种模式、三个档位的区别和怎么用，并在 README 和 taskrail 里加链接。写完告诉你放在哪。
- 我先查清导出慢在查询还是文件生成，再优化最慢那段，用 1 万行报表对比，目标是 5 秒内导出且内容不变；我先按只管网页端来做，报表格式不动。改完把前后耗时发给你。
- 我打算把登录失败的提示统一成一处处理，顺手补上错误码测试；只有一点想确认：要不要连带改 App 端？我建议这次先只改网页端。你点头我就开始。

## 4. 纠偏（human）

- 复述本身就是确认请求；用户指出不对时，用同样的口语重述改过的部分。
- 只重述被指出的部分；被纠正过的同一处不得再错；纠正与原话冲突时以最新纠正为准。
- 多轮仍有分歧：把分歧收成二选一（附推荐）；仍不收敛就请用户换个说法描述目标，不再猜。
- 用户没回话不算确认。

## 5. 代审（goal）

调用：`role-based-reviewer roles=intent mode=review model=<与执行者不同、最好更强的模型>`，随附用户原话、复述、探索摘要。

- 可用性由本 skill 先判断：异源模型不可用时**不调用** role-based-reviewer，按 taskrail 确认协议登记显式降级（写明原因），主会话按下列维度自审，并把所有假设标「把握低」。
- 审查维度：忠实（不添目标、不漏约束）、可检查、假设是否合理、范围是否清楚、上下文是否支撑「怎么干」。
- 通过：无 P0/P1。不通过：按发现修订再审，最多两轮；仍不过则剩余发现写入显式降级，`status: assumed`，继续推进。
- 线上、不可逆、对外发送相关的意图：一律停下等人。

## 6. `wizard/intent.md`

```markdown
---
status: confirmed | assumed
reviewer: <human | 模型名>
---
<给用户的那段口语复述，原样>

## 覆盖清单
- 要干嘛：<目标>；为什么：<…>
- 怎么干：<思路与关键步骤>
- 输出什么：<交付物、落点>；做完的样子：<可检查标准>
- 上下文：现状 <…>；约束 <…>；已有工作 <…>（证据：evidence/intent/…）
- 不做：<…>
- 我的假设：<…（把握高/低）>
- 要你拍板的：<问题 + 推荐；没有写「无」>

## 纠偏记录
- <改了什么，一句话>
```

意图中途变更时直接改写本文件并在纠偏记录追加一行（git 可追溯旧版），流程见 taskrail 契约「意图变更」。

## 7. 结构化示例（`wizard/intent.md` 的覆盖清单，medium）

用户原话：「把导出功能弄快点」；给用户的复述即第 3 节第二条示例。

```markdown
## 覆盖清单
- 要干嘛：让「导出报表」从点击到下载更快；为什么：大报表要等很久
- 怎么干：定位慢点（查询 / 文件生成）→ 优化最慢一段 → 1 万行报表前后对比
- 输出什么：优化后的导出接口；做完的样子：1 万行导出 ≤5 秒（现约 40 秒），内容不变
- 上下文：现状 同步执行、整表查询；约束 不改报表格式；已有工作 上月加过索引（证据：evidence/intent/current.md）
- 不做：不改报表格式，不加新导出类型
- 我的假设：慢在查询（把握低）；只管网页端（把握高）
- 要你拍板的：无
```
