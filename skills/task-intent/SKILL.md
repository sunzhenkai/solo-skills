# 任务意图确认

先对齐「要干嘛、怎么干、输出什么」，再动手。探索要详细，输出要简洁。细则、模板与示例见 [references/intent.md](references/intent.md)。

产出：`{taskRoot}/wizard/intent.md`（无任务目录时只在对话里给复述）；探索详情落 `{taskRoot}/evidence/intent/`。确认后的「输出什么 · 做完的样子」是 `criterion` 的起草来源，下游不得无声改写。

## 流程

1. **探索上下文**：读相关代码 / 配置 / 文档、`tasks/` 历史任务与近期提交，必要时查外部参照；面广时可并行派只读 subagent 分头摸，回简短摘要，详情落 `evidence/intent/`。上下文是复述的一部分，不是可省的前置。
2. **复述**：先按覆盖清单（要干嘛 / 怎么干 / 输出什么 / 上下文 / 不做 / 假设 / 拍板）想清楚，再用 1–3 句第一人称口语告诉用户：做什么、怎么做、产出落在哪、接下来会怎样；最多一个问题自然嵌入。不打标题、不加粗标签、不逐项列字段；结构化内容只写进 `wizard/intent.md`。
3. **纠偏**：
   - human：给用户看复述，按指正只改相关部分，直到用户明确说对；多轮仍对不上就换个问法（如给二选一）。
   - goal：不问人，派异源模型审（`role-based-reviewer roles=intent`），无 P0/P1 即通过，见 references。
4. **落盘**：确认版写 `wizard/intent.md`，`status: confirmed`（goal 审不过时 `assumed` + 显式降级）。

## 不可跳过

- 先查后问：能从仓库、历史任务、对话推出的不问；问必带推荐答案，一次最多一个。
- 只在歧义会改变做法或范围时提问；否则写成「我的假设」继续。
- 复述必须忠于用户原话：不添目标、不漏约束；不确定处写成假设，不写成事实。
- 涉及线上、不可逆、对外发送的意图，goal 模式也必须停下等人。
- 不写代码；探索只读。
- 用户没回话不算确认。

## 何时跳过

（taskrail 契约引用本节，唯一真源。）simple 档且用户原话已含明确目标与完成标准（一句话能描述改动）：不做大范围探索，直接出简短复述请确认。resume 已有 `wizard/intent.md` 且 `status: confirmed` 或 `assumed` 时不重做；human 模式下 `assumed` 只补问一次「对吗」。
