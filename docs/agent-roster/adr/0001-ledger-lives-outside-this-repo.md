# 名册、案例与路由规则一律存放在本仓库之外

本仓库是公开的，而 Roster 天然包含主机名、内网地址与各机器装了什么账号，Trace 里还会带上真实任务内容——这些一旦进入公开 git 历史就无法收回。因此本仓库只存放机制（如何选人、如何委派、如何留痕），全部数据存放在使用者自己的私有位置，由 `~/.config/agent-roster/config.yaml` 的 `data_root` 指出，本仓库不假设它在哪、也不附带任何一条真实记录。

## Considered Options

- **整个仓库转为私有**：结构最简单，自进化机制（`experience/` 随 skill 目录走）原样可用。放弃是因为机制部分本身不含任何敏感信息，把它一起锁起来既不必要，也让这份能力无法被分享或复用。
- **数据存放在 `~/.config/` 下的本机目录**：与本仓库彻底解耦，但名册天生需要跨机器共享——A 机器要知道 B 机器上有什么，各记各的会立刻不一致。

## Consequences

自进化的标准形态要求 `experience/` 随 skill 目录走，这里必须拆开：脱敏后的 Pattern 留在本仓库，带 Host 名的具体案例进私有数据目录。脱敏这一步只能显式做，不能自动搬运。

另外，本 skill 安装到各 agent 目录时是字节复制而非软链，运行时写入 skill 目录只会写到镜像并在下次同步时被覆盖。所以本仓库的目录在运行时一律只读，Pattern 的任何修改都必须回到源仓库进行。

更进一步：同步机制会把 `experience/`、`evals/`、`patches/` 这类创作目录整个排除在分发之外，运行中的 skill 根本读不到它们。这意味着 Pattern 不是运行时可消费的知识，而是固化过程的素材——一条规律要生效，必须被写进 `SKILL.md` 正文或使用者的 `routing.md`。
