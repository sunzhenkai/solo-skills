# 不对 Endpoint 打分，用案例与成文规则代替自动优化

「根据历史结果自动优化任务分配」最直觉的做法是给每个 Endpoint 的各类任务打分、按分数排序。这里不这么做：Disposition 是自然语言描述，Trace 是自然语言案例，选人由 Orchestrator 读证据后判断，累积出的稳定规律再由人确认后写进 Routing Rule。

理由有两条。一是样本量：这类委派一天也就发生几次，几十条记录上的分数是噪声，会让排序看起来客观、实际在乱跳。二是维度：任务类型根本无法预先切成几个格子，硬切出来的 `plan / review / implement` 会把「给一个陌生 Rust 仓库做架构梳理」和「改三行配置」算作同一类。自然语言案例对消费方（LLM）反而是信息密度最高的形式，几条就有用。

## Consequences

系统不会自己变聪明。进化路径是：攒够同类 Trace → 提案 → 使用者确认 → 规律写入 Routing Rule。如果没人做这一步，它就停留在「有名册、有案例、每次现读现判」的水平——这是可接受的下限，但要清楚它不是自动的。
